### 256色白斑诊断与WebP试验方案（2026-10-24）

用户反馈部分从者卡面有明显白斑，拟先定位来源：比对同从者同灵基的原始RGBA裁区、缩放后RGBA、现用P模式PNG及其Alpha分布/量化修复指标，不预设一定是颜色数量或缩图导致。保持原始素材与正式资源不变，在`.workbuddy/editor-evidence/webp-preview-20261024/`输出诊断与样张。使用原始裁区直接缩到现用358×507，再分别编码真彩PNG、WebP无损及有损质量80/85/90/95，复用实际透明通道；不能将现有有损P图转换为WebP作为画质改善依据。选取问题卡面及明亮/细节密集的代表卡面，记录体积、像素差与实际显示效果。

试验只针对编辑器展示用完整卡面；Maa识别模板、共享技能/职阶/头像和既有PNG执行链不变。先得到可审阅的原因及格式对比，再决定是否全量切换。若正式切换，需同步生成器编码/指纹/缓存、manifest媒体白名单与HTTP MIME、相关回归及部署备份，不仅修改扩展名；浏览器卡框尺寸继续保持现状。

### 白斑诊断与WebP样张结果

用户图片对应剑吉尔·德·雷102200的旧512×724卡面。截图中x5/y19起的画面与旧P图合成白底平均RGB差仅0.1609/255。整包源图原生裁区已存在2294个alpha0像素，它们与`max(R,G,B)<=15`的近黑像素集合完全相同，其中1703个集中在头发区域；这些像素的RGB仍保留正常暗部颜色。旧P图的Alpha逐像素等于源裁图，量化护栏修正数为0，故白斑主因是源图近黑像素透明化后漏出浅色底，并非该次256色量化新增。此前透明位置保真检查正确保留了源问题，没有验证矩形卡面应为不透明。现用缩图的262个Alpha分组修正只影响细小边缘，不能解释旧尺寸白孔。

分别试做保留原Alpha和恢复不透明RGB两组样张。直接RGBA→WebP仍保留孔洞；正确流程为从原始裁区先`convert('RGB')`保留透明像素下面的原颜色，再LANCZOS缩到358×507，最后编码WebP，不能先量化或在现有P图上丢Alpha（其透明调色板RGB可能已是绿色），也不能合成到白底把孔洞固化。此不透明策略只适用于有完整背景的矩形展示卡，不能套到窄图/头像或识别图。

使用本机Pillow11.3.0/libwebp1.5.0、method6测试吉尔、阿尔托莉雅、埃列什基伽勒及U-奥尔加玛丽4张358×507卡面：现用256色PNG合计442,907字节；不透明WebP Q90为275,044字节（减少37.900%）、Q95为349,598字节（减少21.067%）；无损WebP为1,017,396字节，大于现用P图。问题图分别为PNG123,112字节（120.2KiB）、Q90 51,204字节（50.0KiB）、Q95 69,514字节（67.9KiB）。不透明WebP均无白孔，解码尺寸与Alpha断言通过；无损版与缩放后的RGB参考逐像素相同。有损版仍存在编码误差，Q90作为体积/细节折中，Q95可优先保留细节；样本体积比例不能直接当作全量收益。

## 六人编队交互约定

编队始终是一行六张竖卡，1–3 为前排、4–6 为候补；属性面板放在卡片下方。窄窗口仅编队板内部横向滚动，不改成两行，也不让整个页面横向溢出。

卡片顶部头像可以更换从者，中部显示星级、等级、宝具与三个主动技能，下部直接打开礼装选择。好友/NPC 标记在右上角；冠位使用三个独立礼装按钮，原有三个礼装对象必须完整保留。礼装使用真实图片尺寸与 `object-fit: contain`，不可统一中心裁切。已有识别礼装图与新补原生横幅的比例不同。

拖动交换复用 `swapMembers`，移动整个成员对象，不能只换 `svtId`，也不能丢失未知字段、技能变体、助战与冠位信息。默认保留战斗动作的槽位编号，并提示检查；用户可撤销。原“交换 / 移动槽位”弹窗保留可用的键盘路径与受限角色重映射，不能在已有换人流程中静默重写后续动作。

头像和拖动把手使用 Pointer Events：移动达到 6 像素才开始拖动，通过 pointer capture 保持事件，通过指针下方的槽位确定目标，结束只交换一次；未达到阈值仍保留点击选择。拖动后抑制误点击，礼装按钮不启用此通路；取消、Escape、窗口失焦、页面隐藏与组件卸载均清理状态。其他区域保留原生 HTML 拖放，不能让原生 `dragstart` 抢走已开始的 pointer 路径。

Pointer 拖动超过阈值后克隆原整卡作为纯视觉浮卡，固定视口定位与源尺寸，保持抓取偏移，使用 animation frame 更新跟随位置；原格子继续占位，目标格高亮。快照移除所有 ID/`data-slot`，设置 `aria-hidden`、`inert` 及 `pointer-events:none`，不能污染命中检测或焦点。结束/取消必须释放捕获、移除快照、停止待处理帧并复原状态；数据或界面切换也取消正在进行的拖动。原生拖放作为兜底保留，沿用整成员交换与撤销路径。

主动技能通过导入的准确 `skillIds` 优先选择变体；没有显式 ID 时才使用槽位默认。追加技能按从者 ID 和 `num`（1～5）查找，缺少第 3 项不能把第 4 项错显示为第 3 项；缺图/缺资料显示未知，不套用其他从者。

## 无回合与显式空回合的执行语义（2026-10-28）

`actions` 缺失、`null` 或空数组表示没有固定回合，保留阵容与助战要求，并从首回合起使用通用自动战斗。`[{"type":"attack","attacks":[]}]` 则表示一个明确的空回合：不安排技能与宝具，使用通用普通卡规则补齐三张卡；不得删除该回合、把它视为无计划，或提前执行后面的回合。

BBC 运行端会将完全空的固定回合折叠为自由战斗，无法无损表达上述纯普通卡空回合。转换器对无累积技能且显式 attacks=[] 的攻击边界明确报错并提示原生战斗；缺失/null/空actions仍不生成round字段，沿用BBC通用策略。有技能的空attacks保留既有转换，不使用伪造动作或额外回合填充。

## 从者自然退场标记与实例身份护栏（2026-10-30）

战斗编辑器在技能阶段的从者头像右键菜单中提供“从者退场”，加入当前技能队列，支持移动与删除。此动作是 MaaFGO 对 Chaldea 数据的扩展，表示等待游戏中已发生的自然退场并确认递补，不会点击或执行任何使从者死亡的操作。技能立即导致退场时，标记排在该技能之后、同回合攻击之前；宝具使用后才退场时，标记排在下一回合开头，不能放在该宝具之前的技能队列中。

动作 JSON 使用当前前排位置 `svt` 与初始编队实例 `actor` 双重记录，两种槽位索引均采用 0 基：

```json
{"type":"retire","svt":0,"actor":{"initialSlot":0,"svtId":100100}}
```

`svt` 范围为 0–2，`actor.initialSlot` 范围为初始六个成员的 0–5，`actor.svtId` 必须是正整数。初始槽位区分同 ID 的自有从者与助战，不能只用从者 ID 作为生命周期或 CD 的身份。退场方案中的从者技能与显式宝具／普通卡也保留同形的 `actor` 护栏；自动普通卡占位不绑定执行者。原始无退场、无护栏的 Chaldea／BBC 方案维持既有格式和按动作时点解释槽位的兼容语义，不因打开编辑器或预览而批量补字段。
