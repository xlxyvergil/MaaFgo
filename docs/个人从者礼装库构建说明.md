# 个人从者与礼装库构建

任务“构建个人从者礼装库”用于扫描玩家当前账号的仓库，为后续自动编队建立可复用的本地持有数据。

## 使用方式

1. 在主界面启动任务。任务会依次点击“菜单 → 编成 → 英灵一览”，进入灵基一览仓库。
2. 在“构建范围”中选择“从者和礼装”“仅从者”或“仅礼装”。
3. 在“礼装识别范围”中选择“全部 4/5 星礼装”或“仅羁绊礼装”。仅构建从者时该选项不会生效。
4. 扫描期间不要手动滚动或点击游戏画面。

任务只会切换灵基一览中的从者/概念礼装页、设置筛选并滚动，不会选择卡片、保存队伍或开始关卡。完成后会关闭灵基一览与编成菜单，返回主界面。

## 本任务专用的小图标模式

“构建个人从者礼装库”会把从者页和礼装页都切到“小图标”，这是库存构建任务的专用设置，不能照搬到自动编队、强化、礼物盒等任务。1280×720 下每行固定显示 8 张卡，纵向行距约 149px；画面通常有 3 个完整行，并露出第 4 行上半部，因此一次截图可处理 24–32 个候选。

原身份模板不会落盘改图，而是在 `inventory_scan_action.py` 中按小图标比例使用 Bilinear 临时缩放：

- 从者 `servant_face` 从 158×158 缩为 118×118。完整行使用较高信息量的面部区域，底部半行使用较短裁剪；两种特征共享同一身份候选和两帧稳定校验。
- 礼装 `EquipFaces/list` 从 147×56 缩为约 110×42，左缘相对卡片为 11px、上缘为 24px。批量特征只用于筛候选，写入前仍以缩放后的完整模板在 ±5px 邻域做 `TM_CCOEFF_NORMED` 复核。

行列不再依赖头像底栏或首排固定 Y 坐标。扫描器用 `assets/resource/base/image/个人库存/稀有度/rarity1_0.png` 的单星模板检测各列星级图标，要求 `TM_CCORR_NORMED >= 0.90`，再用 8 个固定列和 149px 行距联合求当前 Y 相位。只有能组成至少两行、每行至少 4 列的相位才会接受；底部星级尚未露出的半行由已确认相位外推。这样滚动存在惯性时，首排 Y 可以逐屏重新测量，而不是写死。

仅羁绊模式另支持只有一行的列表（包括不足 4 张）：以 `rarity4_0.png` 完整四星条在顶部首行定位，确认下方没有其他四星条后，只识别这一行，不向空白区域外推。礼装身份仍须通过原有完整模板复核和双帧稳定校验。

稀有度模板由 `tools/generate_inventory_rarity_templates.py` 从解包图生成：仅把纯黑背景替换为 Maa 绿幕，保留星星自身的非零暗色描边，以 Bilinear 缩放到 0.74 倍，并增加 1px 绿幕边。源文件、输出尺寸和 SHA-256 记录在 `tools/manifests/inventory_rarity_templates.json`，可以复现而不修改解包源图；生成记录不放入 `assets/resource`，避免被 Maa pipeline Schema 校验器误判为运行时配置。

## 输出文件

- `config/Inventory/player_servants.json`
- `config/Inventory/player_equips.json`

`config` 是本地配置目录，默认不会提交到 Git。写入采用临时文件加原子替换：只有识别流程确认到达列表底部后，才会替换该类别已有的有效 JSON；中止、超时或识别失败会保留旧文件。

每份 JSON 都包含：

- 数据结构版本、生成时间和实际识别数量；
- 项目内目录总数、已有识图模板数、缺失模板的 ID；
- 每个持有对象的 ID、名称、星级、匹配模板和置信度；
- 从者的职阶与羁绊标签，或礼装的羁绊效果与筛选标签。

礼装图片无法可靠判断是否满破，因此当前版本明确写入 `limit_break: null` 和 `limit_break_known: false`，不会猜测满破状态。

## 完整性的含义

`scan_complete` 表示滚动过程已确认到达当前筛选列表底部。`catalog_complete` 表示工程目录中的每一条数据都有可用于仓库识别的图片模板。两者相互独立；例如扫描可以完整结束，但新礼装尚未补图时，`catalog_complete` 仍为 `false`，对应 ID 会列在 `missing_template_ids` 中。

到底判定要求滚动条下沿到达底部、位置稳定及卡片画面稳定，并连续满足 3 轮；仅画面静止或连续识别到相同 ID 不视为到底。滑块较长时也按下沿判断，避免短列表的滑块中心无法达到旧阈值。

仅羁绊模式没有滚动条时，支持顶部一至三行的短列表：用完整四星条确认实际连续行，每个非末行须有至少 4 列星级证据，首屏起每轮双帧布局都一致，连续 3 轮下滑后画面仍稳定，才以 `bottom_detection=short_bond_list` 完成。不会向空白区域外推其他行。出现滚动条时须走滚动条到底判定。

礼装页零命中时先原位重试。仍为零但双帧列表布局有效、或滚动条已在底部时，可以继续滚动和到底检查；确认到底后保存此前可靠识别的礼装，并输出缺图/未识别提示，统计 `scan.zero_hit_pages`。未知礼装不猜测身份，也不写成错误 ID。`scan.recognition_valid=true` 表示列表识别及到底检查有效，不保证每张卡片均已识别；候选中未匹配的卡片计入 `unmatched_candidate_cells`，未入库不代表未持有。

中段连续静止、无法确认布局或底部、超过下滑上限、全程没有可靠身份命中时，仍停止并保留旧库。从者任意一屏重试后仍零命中的保护不变。

从者和礼装都会先执行一次“打开筛选 → 重置 → 决定”，以清除游戏原有的默认筛选，然后第二次打开各自独立的筛选页设置本任务条件。从者会在 `[108,28,433,617]` 区域内一边小幅下滑一边匹配“从者”选项，排除经验值卡、芙芙等非从者项目。礼装全部模式会选择 4/5 星；仅羁绊模式会把礼装筛选页滑到底，识别羁绊效果选项模板并点击模板左端的复选框；点击范围限制在框内，避免随机落点落到文字上方而未勾选。识别采用两帧一致性、最低置信度和第一/第二候选分差三重约束。可见但不能可靠匹配的卡片只计入扫描统计，不会写入玩家库。小图标模式下从者最低分/分差为 0.50/0.06：30 屏只读 A/B 表明，相比 0.60/0.10 仅补回 4 个旧快照内已有且当前画面第一候选明确的 ID；礼装批量候选最低分/分差为 0.85/0.15，完整模板复核仍要求 0.88。

- 无滚动条的羁绊短列表支持一至三行：确认首行位置、连续实际星级行和双帧布局一致，再经过三次下滑确认画面没有移动；不向空白区域外推卡片。
