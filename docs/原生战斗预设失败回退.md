# 主线与地狱的试炼：预设失败后继续默认战斗

自动推主线和地狱的试炼在本场预设技能、换人、从者绑定或出卡流程无法继续时，尝试清理残留界面并改用无预设的原生自动战斗。其他普通战斗仍报错停止。

## 执行过程

1. 本场确实启用了回合方案或试炼专用策略，且发生可恢复的运行错误时才回退。没有方案的默认战斗不会因同类错误再次重启。
2. 先观察当前画面；已确认胜利或战败时直接交回原有结算或战败处理，不关闭终局界面。其他情况先点击现有右上角关闭点。
3. 根据新截图关闭已识别的技能弹窗、目标或宝具选项，取消误开的换人页。选卡页先返回主界面，清除尚未提交的旧选择；已经提交攻击时等待其结束。
4. 确认战斗主界面、排除覆盖层后，启用新的默认运行器：平衡补牌、自动释放识别为可用的从者技能、优先选择可用宝具，不自动使用御主技能。

恢复使用具体界面特征及有上限的等待，不使用画面冻结检测。无法确认可继续的状态时保留现场停止，避免在未知页面继续操作。

预设执行中因残留弹窗而持续识别为未知画面的情况，也允许尝试一次上述界面恢复；只有实际确认回到战斗界面后才启用默认战斗，未知画面本身不代表可以继续点击技能。

## 状态与次数

- 仅当前战斗回退一次；默认战斗再次失败时停止。
- 不修改原方案文件，也不修改后续关卡的配置。下一场重新加载原方案。
- 清除固定动作、目标、从者位置绑定、旧特殊技能选项、开局等牌及试炼颜色／收尾限制。旧从者 ID 只作为无序的视觉识别候选，当前前排重新识别。
- 默认模式重新读取实际技能冷却，不重放原固定技能队列。
- 回退沿用本场剩余回合预算，最多再运行默认上限 40 回合。若旧出卡尚未确认结束，保守预留一个回合预算；预留不冒充已确认完成的回合。
- 方案下载或解析失败、设备异常、手动停止、战斗回合预算耗尽、剧情处理失败等不触发此回退。

试炼回退后的目标是继续完成战斗，不能保证同时满足原方案的附加任务条件。主线战败后的灵脉石续战、缺石撤退重进仍由原有选项控制，此功能不会额外启用它们。

## 接线与验证

入口 `attach.native_battle_preset_fallback` 必须为布尔值 `true`。主线在当前关的独立上下文加入标记；试炼在任务覆盖中加入标记；共享原生入口及其他任务不启用。

相关回归覆盖主线／试炼启用范围、普通战斗停止、真实运行器的技能失败转默认、宝具优先、试炼守卫移除、部分选卡清理、多层弹窗、动画等待、终局交接、手动停止、预算及单次回退。

## 后续测试重点

实机测试后的补充审计增加了离线生命周期集成回归（`tests/test_battle_preset_fallback_lifecycle.py`）：在同一上下文、同一可变方案源连续执行两场，首场回退后下一场重新加载原固定技能、宝具顺序及编辑器高级策略；回退后的战败不进入胜利结算；主线从预设错误、默认战败接到既有灵脉石确认，再以默认逻辑续战。测试使用受控画面状态与执行结果，不操作模拟器或消耗道具。

另以真实 MaaFramework Context、试炼重复挑战调度、编队会话及实际战斗运行循环补测跨场衔接（`tests/component/test_preset_fallback_repeat_framework.py`）：第一场预设失败回退后，第二场仍能读取同一会话并重新执行原预设；结束时清理会话；同一 Tasker 的后续独立任务没有继承回退开关。该测试省略导航与结算页面，画面及输入受控，属于离线组件覆盖。

1. 在合适现场补「真实阵亡导致预设动作无法执行，从而直接触发回退」：本轮已验证回退后的自然阵亡、候补入场与新前排识别，直接由阵亡触发的前半段仍未实测。
2. 补御主换人页取消与多层弹窗恢复。已选两张卡后的取消、主界面确认已由国服实机及原始截图回归覆盖，不必重复。
3. 回退胜利、主线结算回地图已实测；余下可在合适现场补主线战败后按原选项停止／续战／缺石重进，以及下一关恢复原方案的实机衔接。无需专门推进剧情来制造测试现场。

菜单遮挡恢复、九个可用技能实际施放、宝具优先和未开启回退入口的停止行为已有本轮实机证据，后续代码未变时无需重复整场测试。剩余实机项不影响对本轮已验证分支的判断，但不能据此宣称所有阵亡或弹窗组合均已通过。
