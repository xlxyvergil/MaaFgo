# 羁绊数据维护工具

本文说明用于维护 `agent/custom/servant_list.json` 和
`agent/custom/equip_list.json` 中羁绊资料的辅助脚本。脚本仅使用 Python
标准库，建议使用 Python 3.10 或更高版本运行。

## 数据来源与文件边界

- `agent/custom/servant_list.json` 和 `agent/custom/equip_list.json` 是工程运行时
  使用、需要提交到 Git 的结果文件。
- `servant_list.csv`、`equip_list.csv` 和计算器 HTML 是维护者本地的工作资料，
  当前不在仓库中。执行命令时需要显式传入路径。
- Atlas Academy 数据通过公开的 Nice API 在线获取，因此相关命令需要联网。
- 工具不会读取账号、Token 或其它个人配置。

本文命令中的 `<equip.csv>`、`<servant.csv>` 和 `<calculator.html>` 都是占位符，
请替换为实际路径。PowerShell 中路径含空格时应使用引号包裹。

## 日常维护流程

### 1. 检查 Atlas 是否有新礼装

```powershell
python tools/check_atlas_new_equips.py <equip.csv> --region JP
```

该命令从 CSV 当前最大图鉴号开始向后检查 40 个编号，只输出发现的条目，
不会修改文件。可以使用 `--lookahead` 调整检查范围，使用 `--workers` 调整并发数。

### 2. 将已确认的新礼装加入 CSV

先执行预演：

```powershell
python tools/append_atlas_equip.py <equip.csv> <collection-no> --name-cn "中文名称"
```

确认输出的图鉴号、获取方式和羁绊效果后再写入：

```powershell
python tools/append_atlas_equip.py <equip.csv> <collection-no> --name-cn "中文名称" --write
```

写入前脚本会在 CSV 同目录创建
`*.before-atlas-append-<时间戳>.csv` 备份。工具只支持已映射的常驻羁绊目标和获取方式；
遇到未知 Atlas 字段时会拒绝写入，需要先人工确认并更新映射。

### 3. 审计并归档 Atlas 羁绊效果

先执行只读审计：

```powershell
python tools/audit_atlas_bond_effects.py <equip.csv>
```

确认报告中没有异常的未映射效果后再写入 CSV：

```powershell
python tools/audit_atlas_bond_effects.py <equip.csv> --write
```

写入模式会补充缺失的常驻公式及 `bond_effects_atlas` 审计字段，并创建
`*.before-atlas-bond-sync-<时间戳>.csv` 备份。网络请求部分失败时命令返回非零状态；
即使生成了部分报告，也不应把该次结果直接当作完整审计结论。

### 4. 将已核验 CSV 同步到工程 JSON

先预演：

```powershell
python tools/sync_bond_effects_from_csv.py <equip.csv> agent/custom/equip_list.json
```

确认同步和追加数量后再写入：

```powershell
python tools/sync_bond_effects_from_csv.py <equip.csv> agent/custom/equip_list.json --write
```

该工具只同步 `equip.bond` 中归档的五项资料，并可能追加 CSV 中存在常驻羁绊公式、
但 JSON 尚未收录的礼装。JSON 采用临时文件替换方式原子写入，不额外创建备份，
因为结果文件已经由 Git 追踪。

写入后至少检查：

```powershell
git diff --check
git diff -- agent/custom/equip_list.json
python -m json.tool agent/custom/equip_list.json > $null
```

## 重建与历史迁移工具

以下脚本用于从原始工作资料重建羁绊字段，不是日常更新入口：

- `tools/migrations/archive_bond_catalog.py`：从计算器 HTML 中提取静态 JSON，
  归档到从者和礼装 CSV；可选择用 Atlas 补充计算器缺失的从者。
- `tools/migrations/enrich_bond_lists.py`：只为尚无 `bond` 键的工程 JSON 条目追加资料，
  不覆盖已有羁绊内容。

归档到 CSV 时先预演：

```powershell
python tools/migrations/archive_bond_catalog.py <calculator.html> <servant.csv> <equip.csv> --atlas-region JP
```

确认统计结果后在同一命令末尾增加 `--write`。写入前会创建
`*.before-bond-archive-<时间戳>.csv` 备份。

从 CSV 重建缺失的 JSON 羁绊字段时先预演：

```powershell
python tools/migrations/enrich_bond_lists.py <servant.csv> <equip.csv> agent/custom/servant_list.json agent/custom/equip_list.json
```

需要写入时增加 `--write`；只有明确需要把 CSV 中新的高价值礼装追加到 JSON 时，
才同时使用 `--append-new-equips`。`--drop-data-source` 会删除旧版生成的
`bond.data_source` 字段，使用前应单独检查预演结果。

## 提交约定

1. 始终先预演，确认统计和未匹配条目后再使用 `--write`。
2. 只提交工具源码和实际需要的 JSON 数据变化，不提交本地 CSV、HTML 或时间戳备份。
3. 不要把网络请求失败后的部分结果作为完整更新提交。
4. 提交前运行 `git diff --check`，验证 JSON 可解析，并人工查看数据差异规模。
5. 如果脚本新增 Atlas 字段映射，脚本修改与对应数据更新应放在同一提交中，便于复核。
