# 原生战斗识别耗时优化

## Agent 界面日志分级（2026-11-08）

- 代码开关位于 `agent/custom/mfaalog.py` 顶部：`SHOW_VERBOSE_LOGS_IN_GUI = False`。默认只发送警告、错误与 `focus:` 指令；改为 `True` 可恢复 `info/debug` 界面输出。修改后需停止并重新启动任务，新 Agent 才会加载开关值。
- `mfaalog.info()` 和 `debug()` 统一只写本地 `debug/recognition-<进程号>.log`，不会发送给 MXU，包括多行的战斗状态、Chaldea 队伍转换结果及普通进度日志。沿用下述每进程约 12 MiB 的轮转限制，不需要修改 MXU。
- `warning()`、`error()` 同时写本地文件并通过原有 `warn:`、`error:` 协议显示在客户端；`focus:` 任务聚焦指令保持发送。Agent 的启动调试信息也走文件日志，缺少启动参数仍显示错误。
- 羁绊停止/待复核的结果与截图位置、识别超时原来使用 `info()`，现提升为警告，避免隐藏需要关注的停止原因。任务起止等由 MXU 自己生成的界面日志不受 Agent 过滤影响。
- 同步核查了助战、战斗、主线、BBC、导航、礼物盒与强化流程：首个助战兜底、跳过旧方案/开局策略、主线限制编队回退与灵脉石消费、持有上限/QP已满/材料耗尽、BBC拒绝确认或脚本异常停止均保留为警告；导航终止失败和战斗失败出口保留明确错误。普通成功、进度、匹配分数不提升，控制流程与识别参数不变。
- 本地文件不可写时只显示一次明确警告，后续警告/错误仍正常显示；普通和详细日志不会回退刷屏，此时也无法落盘。修复目录权限或磁盘空间问题后需停止并重新启动任务。

## 识别日志开销优化（2026-11-07）

- 全局识别日志器直接读取 `Node.Recognition.Succeeded/Failed` 事件自带的 `reco_details`，保留原来的 OCR 文本和模板匹配分数，不再为了打印日志调用 `get_recognition_detail()`。事件没有附带结果时跳过该条详细日志，不回退到会提取截图的接口。正常识别仍照常获取业务所需的截图。
- OCR/模板详细日志，以及助战候选的头像分数、定位框、技能/宝具/等级判定，编队匹配分数、战斗感知状态等，只写本地文件，不再进入 MXU 的 stdout/stderr 接收和界面日志处理。查找条件、滑动/刷新进度、实际操作、最终结果及需要处理的警告/错误继续显示；识别阈值、条件、等待与点击流程不变。
- 文件在软件根目录的 `debug/recognition-<进程号>.log`，带时间戳、UTF-8 编码。每个 Agent 独立记录，单文件约 4 MiB，保留两份轮转文件 `recognition-<进程号>.1.log`、`.2.log`，每进程约 12 MiB；更早的详细记录会被覆盖，反馈问题时应及时导出。所有文件都以 `.log` 结尾，沿用 MXU 的日志导出/清理。
- 本地详细日志写入失败时只提示一次原因和处理步骤，随后把细节回退到客户端，避免悄悄丢失排查记录。处理目录权限或磁盘空间问题后，需要停止并重新启动任务。
- 历史 Agent 日志的 1857 次真实识别事件离线回放中，原有 401 条识别日志内容一致，完整结果查询由 1857 次降至 0。真实 MaaFramework 内存图片测试也确认模板事件能记录分数且不查询完整结果；这些验证不等同于整机卡顿已经解决，长期效果仍需同场景运行对照。

## 问题与实施范围（2026-10-31）

手机端 2.0.16 的一场三回合战斗耗时约 7 分 48 秒。框架日志显示，换人界面识别 64 次累计约 67 秒，三个敌人各识别 19 次累计约 67 秒，进本告知弹窗检查 3 次累计约 45 秒。这是识别调用耗时，部分与游戏动画等待重叠，不能直接当作可节省时间。

本次先减少无关识别，不降低识别阈值，不缩短原有加载、技能和换人动画保护时间：

1. 特殊编队提示先识别小范围操作按钮，再检查正文/限制条件；仍须满足原有全部条件才点击。调整 And 顺序时同步修改 box_index，保持原点击位置。正文保留颜色过滤以避免批量 OCR 提前计算；不改普通告知和特殊编队的分发优先级。
2. 普通技能返回、出卡动画等不等待换人的轮询跳过换人 OCR。真正等待换人时保留原检测优先级；首次完整场景识别仍能识别已打开的换人界面。
3. 指定敌人的技能和目标点击复核，只读取该敌人槽位，仍逐次使用新截图确认存活、场景置信度和选中态。常规决策及选卡保留完整敌人信息，不复用可能因伤害/即死/换波而过期的数据。
4. 胜利、失败、换人及未知界面不读取敌人战斗数据；终局检测后不再把报酬文字当作敌人做 OCR。

验证须覆盖：无弹窗快速拒识、合法限制提示与点击框不变、换人仍能识别、技能目标切换及目标消失、选卡目标决策、胜败页面不再访问敌人节点。使用现有截图做真实 MaaFramework 离线回放，不操作设备；手机端实际提速须后续同设备日志确认。

## 联合 MaaMCP 实机验证

2026-10-31 在同一台日服模拟器完成联合验证，三个被测代码/资源文件按 SHA256 冻结，运行期间没有改动：

- 地狱试炼的普通技能返回不再做换人 OCR；御主换人步骤保留换人识别，实际换入从者并继续执行后续技能。
- 日服种火初级实际切换敌人 `2→3→1→2`，每次使用新截图确认选中态，只读取目标槽位；普通观察仍读取全部敌人。
- 两场种火初级均 4 回合获胜并自动结算返回曜日列表；VICTORY 完整感知不再读取敌人 OCR。试炼专用失败蓝窗接入共享失败节点后，真实 DEFEAT 完整感知同样跳过敌人 OCR。
- 开局等牌两回合期间没有提前释放计划技能或宝具；第 3 回合满足条件后回到主界面再执行原计划。完整初始编队已知时，特殊技能检测按已确认的六名从者收窄；从战斗中直接启动且没有实际编队会话时，仍使用完整识别兜底。

特殊编队弹窗正例来自国服截图包，目前没有已确认可复现的日服入口，实机只覆盖无弹窗路径。以上验证证明分支行为，没有据此推算手机端整场耗时收益。详细日志、截图、哈希和边界记录在 `.workbuddy/runtime/maa-mcp-data/evidence/advanced_strategy_live_20261031/continuation_peer_audit.json`，高级策略与原方案回填另见《原生战斗高级策略实施方案》。
