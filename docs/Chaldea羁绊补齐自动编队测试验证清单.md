# Chaldea 羁绊补齐自动编队测试验证清单

## 1. 文档用途

本文档用于持续记录「Chaldea 自动补齐从者和羁绊礼装」的待测场景、实机结果、
失败现场与回归结论。功能逻辑发生变化、实机暴露新问题或完成一轮验证后，应直接更新
本文档；不要另外创建带日期的重复测试清单。

设计与业务规则见
[`Chaldea羁绊补齐自动编队方案.md`](Chaldea羁绊补齐自动编队方案.md)。

状态约定：

- `待验证`：尚无足够证据。
- `部分通过`：离线或局部分支通过，但未完成端到端实机验证。
- `通过`：已在真实游戏界面覆盖预期分支，并取得截图或关键日志。
- `失败`：实际结果不符合预期，必须记录问题和故障现场。
- `阻塞`：当前账号、队伍或库存无法构造该场景。

## 3. 每轮实机测试的固定流程

### 3.1 测试前

1. 记录使用的 Chaldea 队伍 ID、补齐选项、羁绊基础值和预期星级顺序。
2. 截图并记录原队伍六个槽位、助战位置、已有礼装及 `used/max COST`。
3. 明确本轮要覆盖的测试编号，不为顺带提高覆盖率而擅自更改玩家领取、强化或库存。
4. 确定安全恢复方案；恢复只能还原本轮测试造成的编队修改，不改动其他队伍和资源。

### 3.2 运行中

1. 记录关键节点：进入配置页、首次 COST、每个星级首屏、每次最终选人、每次装卸礼装、
   最终决定及二次确认弹窗。
2. 识别失败、超时、误点击、进入意外页面或命中错误恢复分支时，立即把它当作“现场
   断点”：先暂停会继续点击、后退或返回主界面的流程，再截图和检查识图详情。
   MaaMCP 测试 override 应设置 `debug_preserve_failure=true`；该参数不进入用户选项，
   正式运行默认关闭。
3. 识图故障至少保留：完整截图、实际 ROI、模板、最高分、阈值、第二候选分数、候选框/
   点击坐标、最后成功节点及异常节点日志。不得只查看已经返回主界面后的最终截图。
4. 调整 ROI、裁剪或阈值时，使用故障帧离线复现，并与同屏全部候选比较；不能只验证
   目标模板自己的得分。

### 3.3 测试后

1. 重新识别五名本地从者和所有本地礼装，确认助战及其礼装从未被编辑或计分。
2. 读取最终 COST，确认 `used <= max`；重新计算实际羁绊值并与日志计划值比较。
3. 检查 Chaldea 指定槽位和原有礼装均未被覆盖。
4. 恢复测试前队伍并截图复核。仅在现场材料已保存后执行失败恢复。
5. 更新本文档对应测试项的状态、日期、队伍 ID、结果和证据位置。

### P0-08 礼装库存缺失后的联合重规划

- 状态：`部分通过`
- 前置：构造最优礼装不在玩家仓库、次优礼装存在，并且缺少最优礼装会改变最佳从者或

  后续不再扫描该缺失 ID，最终只装备已确认存在且不重复的礼装。

## 8. 更新规则

- 修复代码不自动把测试项改为“通过”；必须有修复后证据。
- 离线模板匹配不能替代完整实机流程，只能记为“部分通过”。
- 新发现的问题先追加到最贴近的测试项；若属于独立风险，再新增编号，避免用笼统备注覆盖。
- 调整阈值、裁剪、ROI、滑动距离、次数上限、两个其他位置选项、本地库存模式、库存预检
  或错误恢复路径时，至少回归 P0-01、P0-05、P0-07、P0-08、P0-09、P0-10 及直接受
  影响的测试项。
- 测试截图和临时 override 不作为正式业务资源提交；需要长期保留的证据应使用稳定命名并在
  本文档记录路径。
- 测试中若出现未覆盖的新异常，优先保存现场、记录复现条件，再决定是否继续；不得为了
  完成清单而绕过保护规则。
