# 编队编辑器启动与旧服务接管

2026-10-28。启动器、服务会话和API连接的独立改动，不调整编队或战斗业务；其他任务的业务修改与构建资源保持。

## 启动行为

- 同一安装目录的健康服务继续复用；另一目录留下的兼容编队服务可以被本次启动替换。
- 替换前检查新目录的服务入口及前端产物，再核对旧服务的健康信息、PID、进程创建时间、实际监听端口和启动参数。普通端口占用或身份不明确时仍报错，不能按端口强杀程序。
- 经认证的正常退出接口结束旧服务，等待旧进程完成已接收请求并退出，然后启动本次目录的服务；超时明确报错，不强制杀死旧进程。每个端口的启动操作跨进程串行，避免两个启动器同时接管。
- 启动结果记录被替换的旧目录及PID。状态查询和单独停止仍只针对当前安装目录；命令行可以禁用自动接管。

## 数据边界与风险

后端正常退出会等待已接收的保存完成，已有方案、草稿和备份留在原目录，不迁移、不删除。尚未上传到后端的修改仍在旧浏览器页面中；切换会让旧页面断线，可以先下载JSON保留。正在进行的长请求可能使接管等待超时，需等待它结束后重试。

“另一安装的服务”不等于“无人使用的残留进程”。从另一目录启动时，即使旧页面仍在编辑，也会断开它；不会结束MXU或游戏进程。需要同时使用两份编辑器时，应指定不同端口，或用`--no-takeover`保持原来的拒绝接管行为。

新启动页面携带项目身份。前端首次绑定后不会因重连改变身份；所有API附带项目身份，新启动的服务要求此身份才能建立会话。旧页面面对另一目录的服务不能获取新会话并自动保存草稿，旧版缺少身份绑定的页面也会被拒绝重连。用户应从本次启动器打开的新页面继续编辑。

同目录健康服务复用仍保留已有行为，不把每次点击都变成重启。若服务无健康响应、身份不明或拒绝正常退出，启动器不会强行终止进程。
