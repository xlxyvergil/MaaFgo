# 茶壶开关模板来源

2026-11-01 从本地 `FGO整包` 的已拆分原始按钮生成识别模板：

| 服务端 | 整包中的相对路径 | 项目模板 |
| --- | --- | --- |
| 日服 | `图标拆分/Terminal/btn_boostitem_on.png`、`btn_boostitem_off.png` | `base/image/battle/teapot/bar_toggle_on.png`、`bar_toggle_off.png`、`toggle_on.png`、`toggle_off.png` |
| 国服 | `国服图标拆分/Terminal/btn_boostitem_on.png`、`btn_boostitem_off.png` | `cn/image/battle/teapot/bar_toggle_on.png`、`bar_toggle_off.png`、`toggle_on.png`、`toggle_off.png` |

原始图标为 62×62 RGBA。使用 OpenCV `INTER_LINEAR` 缩放为游戏 1280×720 基准下的 68×68，再取 `[y=8:40, x=12:56]`，输出 44×32 的 BGR 模板。裁区位于按钮内部，不含透明边缘，也不包含游戏叠加的剩余时间、库存及按钮下部。

原始按钮本身不含倒计时，但游戏会把倒计时覆盖到按钮下方，所以不能直接使用整个原始圆形按钮。截图模板此前包含了这部分文字，现已替换。所有模板仍使用原有 0.90 阈值，Pipeline ROI 和点击位置保持原值。

`tests/unit/test_teapot_vision.py` 使用国日服历史实机截图裁区回放，并将倒计时改为不同文字，验证两种状态仍能正确区分；转场帧由茶壶图标和开关联合识别，不能仅凭按钮认定为茶壶状态。

## 入口说明与帮助图标

`entry_icons.png` 来自整包的 `Terminal/questinfo_btn_01.png`（i）及 `Battle/btn_icon_help.png`（?）。日服使用 `图标拆分`，国服使用 `国服图标拆分` 中对应的原图。

这两个 34×34 导出 PNG 的 alpha 全为 255，图标外部为黑底，不能把它当作有效透明通道。分别缩放到 42×42；在原始坐标上仅保留以 (16.5,16.5) 为中心、半径 12 的圆形内部，再将该掩码按最近邻缩放到 42×42。两图以横向 44px 间距合成 86×42 模板，其余像素设为纯绿 `#00FF00`，不保留阴影、边缘或截图背景。

引用该图的“茶壶-识别交替过渡”及“茶壶-识别任意入口”均启用 `green_mask: true`。纯绿色区域不参与匹配，因此主线进度导致的背景色变化不会成为识别依据，仍要求两个图标共同出现。

视觉回归会保留历史截图中的真实图标并改变周边底色，验证国日服模板的正例及缺失任一图标的负例。`tests/component/test_teapot_entry_mask.py` 另以 MaaFramework 内存控制器验证实际绿幕掩码识别，不连接设备、不执行输入。

## 国服道具自动使用弹窗

国服第一种 UI 的弹窗位置、背景及语言与日服不同。`cn/pipeline/原生战斗茶壶.json` 使用标题 OCR“道具自动使用设定”与右侧茶壶图标联合确认弹窗，开关状态再限定到右侧 ROI；不依赖日服的弹窗背景模板。所有内联 OCR 均有独立 `sub_name`。

2026-11-01 用户截图中，左侧风暴罐为开、右侧茶壶为关，库存为 47。截图小裁区用于原生 MaaFramework 只读回放：关闭态、开启操作守卫、关闭弹窗守卫均通过，开启态与关闭操作守卫均不通过；去掉标题或茶壶图标时全部拒绝。开关模板仍来自整包，不包含截图中的倒计时。此验证不代表已在国服第一种 UI 中实机点击切换。
