## 调用

1. 将所需 JSON 放进所用客户端的 `config/Battle`。本批交付已在开发目录和本机打包版各新增这 7 个文件，未覆盖原有配置。
2. 在编队与战斗编辑器中选择“从 config/Battle 选择”检查或调整；也可以通过本地 Chaldea JSON 导入。
3. 战斗任务选择 **Chaldea 队伍导入**，填入完整 JSON 文件名；战斗执行使用**原生自动战斗**。助战模式选择**使用编辑器/Chaldea配置**。BBC 转换无法完整表达这些带实例绑定及补牌策略的脚本，不应改用 BBC 执行。
4. 开始前在游戏内核对本队的冠位三槽礼装、羁绊效果、天赋树、从者及御主礼装等级。当前自动编队会跳过冠位从者的礼装修改。

## 转写选择与使用条件（以下按原图编号）

- 02～06 的截图没有助战标记，本批将主输出设为助战；08、13 严格保留截图第二槽助战。前排次序与截图一致。后三槽“不要求”，不会自动清空游戏中已有的候补。
- 02 中莱妮丝、龙马的魔力装填记为 **Lv1，至少10% NP**；03、04、06 指定角色及 08 全员、13 双太公望按图要求记为 **Lv10，20% NP**。05 采用非冠位莱妮丝分支，莱妮丝、太公望均需魔力装填 Lv10。
- 02、03、04 中两位冠位均为羁绊 **NP50**；05 的拉二为 NP50；06 的君十一、梅芙均为 NP50。
- 08 的太公望保留**初始羁绊效果**，梅芙使用 **NP50**；这是根据图中充能路线补全的开关。梅芙必须解锁冠位树初始10% NP。其宝具、技能强化和天赋树条件不能省略。
- 13 的两个太公望均保留**初始羁绊效果**：20附加＋自身50＋另一位太公望20＋圣诞尼莫10＝100% NP。双太公望使用不同的初始槽位绑定，避免同名从者混淆。
- 03 水飞嫂2的目标未在图中写明，本批设为灰姑娘；02 中“龙马全技能12”的重复数字按1/2/3各使用一次转写。
- 08 将攻击目标设为屏幕左侧敌方（Chaldea `enemyTarget=2`，原生敌方槽1），对应原图“左上70万血的马”。这是固定槽位，**不会按70万HP自动找敌**，请核对实际战斗位置。
- 13 使用原生普通卡策略实现“有绿卡则选绿卡”：两个宝具固定占第1、2张，第3张默认补牌，Quick 权重100，其余牌色和额外连携权重0。手牌识别成功且存在可攻击绿卡时优先绿卡，无绿卡时选其他普通卡，不会等待不存在的指定从者绿卡。
- 御主服均暂记 Lv10。其他图片中未明确给出的金芙芙、具体 ATK、天赋树节点 ID、关卡 ID 均未臆填；高ATK与树节点要求保留在每份 JSON 的 `_guideNotes` 中。`skillIds`、`tdId` 记录所需强化版本，但不会自动替玩家完成强化。
- 仅设置一个固定回合。伤害不足而未结束时，脚本结束后会恢复原生通用战斗策略。原图有替换建议，但替换角色需要重新检查充能与技能，本批只生成图示主阵容。

## 验证范围

已逐份检查 JSON 读取、编辑器能力校验、原生回合转换、技能目标和顺序、宝具顺序、助战条件解析、普通与追加礼装助战模板。已用本机打包版的实际 Python 与模块重复检查；13 的补绿卡策略以人工构造手牌分别检查有绿卡和无绿卡分支。

这些是数据与决策验证，尚未进行模拟器通关测试，不能保证图示配置以外的等级、宝具、天赋树、ATK、发牌或技能命中结果也能一回合完成。

从者、技能、强化宝具及羁绊礼装 ID 根据工程离线资料与 Atlas Academy JP 数据交叉核对。实际查询地址保存在各 JSON 的 `_guideNotes.dataReferences`。
