# 搓丸子使用与维护说明

更新日期：2026-10-30。当前状态：**待实机校准**。

“搓丸子”将允许消耗的低星概念礼装强化为经验素材，可按配置联动友情召唤、目标保留、经验值卡存储／贩卖及从者升级。任务入口位于 MXU“日常行为”分组，名称为“🍡 搓丸子（待实机校准）”。礼装制作与从者喂养使用不同材料，分别配置。

## 配置与使用

默认采用“正常运行”，只处理现有礼装：启用自动搓丸子，制作 **1 星丸子**，仅允许消耗 **1、2 星礼装**；抽友情、保留目标、存储、贩卖、成品入库和自动喂从者均关闭。

| 配置 | 含义与默认值 |
| --- | --- |
| 丸子星级 | 选择制作 1 星或 2 星丸子，默认 1 星；不是素材筛选开关 |
| 额外允许消耗的礼装星级 | 默认仅 1、2 星；可独立增加 3 星、4 星或同时增加，两者互不连带 |
| 自动抽友情 | 默认关闭；开启后默认每批 10 抽、向左寻找友情池、最多 50 批、保留友情点 0 |
| 保留对象 | 默认关闭；最多配置 5 组从者／礼装，按目录选择稳定 ID，选择指定份数或全部保留 |
| 经验值卡整理 | 四星、五星独立选择存储或贩卖，默认均关闭；只处理已核验身份且未锁定的经验值卡 |
| 满级丸子存入保管室 | 默认关闭；只处理本轮制作且能唯一重定位的成品，不整理历史成品 |
| 自动喂从者 | 默认关闭；开启后选择单个目标从者与目标等级 |
| 贩卖时 QP 已满 | 默认停止；继续处理须由用户明确选择 |
| 最多处理轮数 | 默认 200；与抽取批次上限分别限制处理与召唤循环 |

首次使用建议保持默认素材范围，核对需要保留的礼装已锁定，并检查游戏现有友情点自动变还设定。任务不会替用户修改该设定。完成配置后，从主界面启动更便于核验导航与类别；无法可靠确认页面或对象时会停止并报告原因。

启用保留目标时，指定份数按**本次新增且确认成功的锁定**计数，原已锁定对象不扣减份数。同类同 ID 的重复配置合并额度；“全部保留”使用独立选项，不以数量 0 表示。“全部满足后停止”要求至少一个有效有限目标，不能与无限保留条件组合。

“仅测试从者选择”只定位所选从者，不抽取、贩卖或提交强化。仍需填写合法目标等级。游戏可能因原有自动配置开关而预选经验卡；测试成功前会清除这次预选，核验 **20 个素材槽为空、所需 QP 为 0**，保留自动配置开关状态。正常升级模式不执行这项测试清理。

## 保护规则与当前限制

- 首版只从未锁定、未标记、Lv1 的 1／2 星底卡开始。锁定、标记、保留目标、已有经验的个体和身份不明对象不作为普通素材；不会自动解锁历史库存。
- 未达到最终等级上限时，需要核验同名卡突破条件。1 星成品须实际达到 **50/50**，2 星须达到 **55/55**，再确认锁定与标记，才计入成品数量。
- 额外允许 3／4 星不等于允许整批直接确认。只有本批实际选择的高星素材均完成身份与保护复核，才局部授权额外确认。
- 本轮素材不足时会尝试保护半成品并复核；**跨次自动接手历史半成品与恢复记录尚未开放**。
- **100 抽不能与保留目标组合**，参数阶段拒绝。100 抽实际提交及完整结果遍历仍需实机验收。
- **友情从者贩卖、纹章贩卖尚未开放**；启用后会在游戏输入前明确拒绝，不忽略开关继续执行其他操作。
- 候选与整理列表最多检查 12 页。只有明确识别到底才报告无可处理对象；末端未知、页数耗尽、同 ID 个体歧义或选择数量异常均停止。
- 保管室满、QP 满／不足、友情点不足、预算达到、无进展和用户中止分别处理，不自动扩大消耗范围。

## 维护入口与流程约束

| 入口 | 职责 |
| --- | --- |
| `assets/tasks/搓丸子.json`、`assets/options/搓丸子.json` 及其子目录 | MXU 任务、功能开关与目标选项 |
| `tools/generate_expball_options.py` | 从现有目录生成任务与选项；支持 `--check` |
| `agent/custom/expball_action.py` | `execute_expball` 调度、额度、材料复核与跨轮编排 |
| `agent/custom/expball_policy.py`、`expball_catalog.json` | 参数、材料规则及从者／礼装身份资料 |
| `assets/resource/base/pipeline/搓丸子入口.json`、`搓丸子.json` | 正式入口、礼装列表、强化与保护分支 |
| `assets/resource/base/pipeline/友情召唤.json` | 友情池身份、抽取确认、结果与目标锁定 |
| `assets/resource/base/pipeline/搓丸子整理.json`、`搓丸子从者.json`、`搓丸子网络.json` | 整理、从者定位／测试清理、共享通信保护 |
| `assets/resource/cn/image/servant_face/` | 国服从者头像按同名路径覆盖基础资源；未覆盖的文件回退基础资源 |
| `agent/main.py`、`assets/interface.json` | Action 注册、任务与选项导入 |

页面识别、OCR、模板、选中边框、点击和等待由具名 Pipeline 完成；业务读取识别结果，不新增脚本全图扫描。导航、筛选、贩卖与强化复用既有每日友情、整理礼物盒和强化从者流程，覆盖与实例回调仅在本任务内生效，避免改变独立任务行为。

礼装列表统一为七列小图标布局，候选预览使用中心点长按；修改网格、显示密度或预览动作时，必须同步核验底卡、素材、成品和保管室列表。图像资源按基础与国服覆盖关系解析，新增正式日服图放入 base 对应目录；候选头像命中后仍须精确名称复核。

免费友情按钮、召唤确认、开关、帮助锚点、空槽与排序决定复用现有资源路径。详情关闭、锁态和保管室共用同一份模板；国服与基础资源像素完全相同的图片只保留基础层副本。礼物盒经验卡图标与强化／贩卖卡片的显示方式不同，不可仅因名称相近替换；星级已选与未选状态也必须区分。

空格背景有动画，空位模板未命中不能当作有卡；候选预览前由Pipeline在单格顶部正向识别Lv／等级文字。当前底卡在重选列表中有“はずす／卸除”标志，应关闭列表沿用已选对象，不能再点击卸下；选定后还须读到实际等级／上限。详情关闭点击收窄到按钮中心，避免随机落到识别框边缘。素材页关闭与决定按钮继续复用工程已有模板，不降低原阈值。

QP不足必须同时包含QP／量子与明确的不足文案，“所持QP”余额本身不能触发。若在普通强化确认框暂停，后续仅从确认分派继续，不重新进入提交强化；实际等级与上限增长、身份不变才证明该批强化完成。

从者定位先核验从者强化场景，防止与礼装强化共用图标混淆。已选短路要求标题与精确姓名同帧成立；小字不可读时回退到已确认的资料页读取大字姓名。错名保留资料现场并停止，成功才关闭。已选页面就绪判断、回主界面路径及测试清理使用本任务局部接口，正常从者升级和旧独立任务保持各自语义。

通信重试须联合核验弹窗正文与右侧重试按钮，最多 **3 次**；耗尽后先停止，不能把弹窗后方页面当作成功。召唤、存储、贩卖和强化的消耗提交最多执行一次，恢复等待不重新进入提交入口。业务必须核验唯一预期终点，框架任务成功或“无通信弹窗”本身不等于业务完成。

每次调用重置本轮相关命中计数，局部覆盖不能泄漏至下次调用。贩卖筛选的滚动定位只在筛选窗口身份成立时执行一次，后续仍受原短滑次数限制；存储不安装贩卖专用覆盖。整理前要求选择数为 0，单张选择后要求为 1，数量不符不得提交。
