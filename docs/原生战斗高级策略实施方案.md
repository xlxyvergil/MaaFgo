# 原生战斗高级策略实施方案

状态：先完成本文规划，再实施；已完成开发与离线验收，2026-10-31。

## 目标与默认值

将原有试炼专用策略整理为所有原生自动战斗共用的「高级策略」。默认选择「默认」，只有「手动」展开后续选项。

| 模式 | 行为 | 后续选项 |
| --- | --- | --- |
| 默认 | 使用统一内置默认值，忽略旧手动设置和方案中的高级策略 | 无 |
| 使用编辑器/chaldea配置 | 从实际使用的同一份方案读取全局高级策略，缺字段回落统一默认值 | 无 |
| 手动 | 使用 MXU 中的手动设置，忽略方案中的全局高级策略 | 补牌预设、开局等牌、策略微调、最大回合、自动补放技能 |

统一默认：平衡补牌、不开启开局等牌、自动补放从者技能开启、最大战斗回合 40。等牌开启后的默认预算为 2 回合；目标从者和需要的牌色必须明确设置。补牌微调默认为 `{}`，不预设试炼专用从者、宝具颜色或主输出。

「自动补放」仅在当前没有固定回合方案时生效；方案内明确的技能、宝具、普通卡及其顺序始终优先。默认补牌不会自行新增计划未要求的宝具。

## 持久化契约

在 Chaldea BattleShareData 顶层新增 MaaFGO 扩展字段 `maaAdvancedStrategy`，不占用上游模拟参数 `options`，不将 MXU 的来源模式保存到方案中：

```json
{
  "maaAdvancedStrategy": {
    "preset": "balanced",
    "openingHand": {
      "enabled": false,
      "servantId": null,
      "servantSlot": null,
      "requiredColors": ["B", "Q"],
      "maxWaitTurns": 2
    },
    "nativeStrategyOverrides": {},
    "autoServantSkills": true,
    "maxTurns": 40
  }
}
```

`preset` 候选：`balanced`、`mighty`、`brave`、`np`、`legacy`，对应现有五个补牌预设。`nativeStrategyOverrides` 保持现有补牌 JSON 的 snake_case 字段约定。独立开关和等待预算最后应用；目标从者、牌色可用专门字段或现有微调字段设置，不因空专门字段覆盖有效微调。回合范围 1–100，等待范围 0–5。错误类型和非法值需在编辑器及运行入口明确提示，不静默接受错误设置。

运行时与编辑器后端共用纯 Python 高级策略默认、预设和校验模块。导入的老方案没有该扩展时显示默认值，保持原始数据，不因浏览而新增字段；实际编辑后保存新字段。未知扩展信息遵循现有无损保留规则。

## UI 与资源接入

新增共享 `options/原生自动战斗高级策略.json`，策略通过独立配置节点的 attach 字段传递，防止队伍导入或多次战斗重写 `custom_action_param` 时丢失。

挂载范围：

1. `战斗方式.json` 的原生分支末尾，覆盖直接战斗、日常、冠位、通用大小活动、迦勒底之门。
2. `自动推主线.json` 的原生分支末尾。
3. `tasks/原生自动战斗.json` 最后。
4. `tasks/地狱的试炼.json` 最后，替换原先独立的策略选项。

旧试炼专用策略节点不再决定新的默认行为，试炼专用身份及颜色不能泄漏至其他任务。现有「使用 Chaldea 配置」等相关显示文案统一为「使用编辑器/chaldea配置」，保留已有内部 option/case 标识，兼容保存配置。

编辑器在「动作属性与高级出卡」下面增加独立的「全局高级策略」栏目，默认收起。没有选中动作、没有动作或编队时也可编辑。使用原有修改/撤销/重做/草稿/保存/导出流程，加载与切换方案时显示对应方案的策略。新方案及表单默认与 MXU 一致。

## 运行顺序与兼容

1. 读取入口参数和高级策略来源。
2. 必要时获取方案一次，同时用于阵容身份、回合计划及高级策略，不为不同字段重复下载。
3. 按来源白名单合并策略，保留明确的 `plan`、方案来源和其他执行参数。
4. 规范化从者身份，再解析 profile/policy，创建决策器。

兼容老方案、空 actions、无回合方案、无 team、仅全局策略文件，以及无方案直接从战斗启动。无队伍资料时不猜测卡牌归属或宝具颜色。仅策略文档仍需按明确文档结构识别，不能把任意 JSON 当作战斗方案。

开局等待依赖原计划首回合；没有有效回合方案时跳过等待并记录原因，不阻止普通战斗。有计划且用户明确启用时保留现有场景确认、身份一致与等待预算检查。

助战兜底、主线受限编队、续战清理旧方案后，不能读取旧队伍身份或旧编辑器策略；编辑器模式回默认，显式手动非阵容策略可以保留，开局等待关闭。中途启动默认不等待。

## 工作划分

- 资源与 MXU：共享选项、任务挂载、pipeline 默认、显示文案及资源结构测试。
- 运行时：共用策略模块、来源解析与合并、无方案兼容、下载复用、兜底处理及逻辑测试。
- 编辑器：全局栏目、模型默认、无损更新、后端校验、构建产物及模型/API 测试。
- 集成：跨模式与入口核对、现有回归、浏览器核验和文档更新。

## 验收

- 三模式显示与默认值符合上述表格，默认/编辑器模式不展开手动项。
- 所有原生入口均可访问共享选项，BBC 分支不出现。
- 默认/手动/编辑器来源互不串用，旧方案按统一默认运行。
- 同一方案的全局策略保存、重载、撤销、切换及导出往返一致；无动作时可用。
- 无方案、仅策略、仅编队、仅动作、固定计划、计划结束后的策略行为可验证。
- 固定技能与出卡不被全局补牌覆盖，已有身份识别及初始编队行为保持兼容。
- 运行 `python tools/run_tests.py --suite static`、针对性 Python 测试、编辑器模型测试及生产构建；本机检查折叠面板和保存重载。
