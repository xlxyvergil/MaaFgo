# 自选助战候选礼装

在自定义助战的礼装设置中，选择满破或非满破后，将“选择方式”切换为“多选”，即可勾选多个候选。普通助战和冠位 1、2 号礼装均支持。每格内部是 OR，冠位两格之间是 AND；羁绊礼装效果和其他英灵条件仍按原设置匹配。多选不勾选任何礼装表示不限此格。切回“单选”会使用此前保存的单选礼装，忽略多选候选。

保留原 `scan_select` 键和类型，并通过新增的选择方式选项路由到单选或标准 PI `checkbox`。这样无需升级或修改客户端，旧任务的单选值也不会因控件类型变化被重置。Android 打包继续转换原有动态单选，新增多选直接使用标准 PI 定义。

三个槽位、两种满破状态的选项由以下命令生成和检查：

```powershell
python tools/generate_support_ce_options.py
python tools/generate_support_ce_options.py --check
```

新增或删除 `assets/resource/base/image/lizhuang/满破`、`非满破` 中的正式模板后重新生成，并提交对应选项 JSON。多选列表不包含空模板；默认空勾选即表示不限。

多选模式写入 `<原单选键>-多选=true`。每个被选 case 分别写入 `<原单选键>-候选:<文件名>=true`，避免多个 case 的数组或嵌套对象在覆盖时丢失候选。单选模式明确写入 false，不读取残留候选；框架任务覆盖不修改资源本体，下一任务取消勾选的候选也不会保留。

各槽位的 `<槽位名>-状态` 优先于旧的共用 `礼装状态` 字段；没有新字段时沿用旧字段。Chaldea 导入仍按其每格指定的礼装和状态匹配，不受自选多选条件影响。

## 可选礼装扩展

在 HTML 编队编辑器的“选择概念礼装”弹窗，点击“安装礼装扩展”，选择发布的 ZIP。服务根据本次编辑器绑定的安装目录，校验并安装到 `config/SupportCE`，安装后立即刷新礼装列表；仍勾选“常用礼装”时，需要取消该勾选才能看到新增礼装。“常用礼装”不会因扩展包扩大。主程序的内置模板优先使用，缺少的模板才查询外置包。

压缩包根目录为 `manifest.json`、`满破/`、`非满破/`，不能再套一层 `config` 或 `SupportCE`。清单使用 `schemaVersion: 1`、`type: "maafgo-support-ce"`、`name`、`version`、`equips`；每条礼装保留整数 `id`、显示 `name`、按状态映射到 PNG 的 `templates`，可带完整 `sha256` 图片哈希。图片必须为完整的 158×44 静态 PNG。新增礼装按 ID 关联，译名不同或同名礼装不混用。仅有外置助战图片的礼装只开放助战卡面选择，不据此宣称可以自动编队。

安装时先检查整个 ZIP，再替换该专用目录；校验失败不更改已有扩展。上一次安装保留在 `config/SupportCE.backup`，最终替换失败时自动恢复。新包会整体替换旧包，维护时应打包希望继续提供的全部外置礼装。手动解压或更换目录后，需要重新打开编辑器刷新目录信息。

原生 MXU/Android 自定义助战将“选择方式”切换为“扩展礼装（可多选）”：勾选一个为单选，多个候选为 OR，空勾选仍表示不限。该列表随版本从 `equip_list.json` 生成，因此可能包含未安装的礼装；缺图时任务会提示在编辑器安装扩展。HTML 编辑器则按实际安装状态刷新“仅显示助战可识别礼装”。原有“单选”“多选”继续使用内置列表。

扩展模式写入 `<原单选键>-扩展包=true` 与独立的 `-扩展候选:support-ce:<礼装ID>`，切回原模式时明确关闭扩展标记，避免读取另一种模式的残留选择。普通与冠位两格均适用，冠位羁绊效果槽不受影响。

生成可选包使用本地 `skills/fgo-equip-icon-pipeline/scripts/build_support_extension.py`，遵循该 skill 的源图检查、dry-run、生成和 ZIP 校验流程。扩展图片不会加入主包 `assets/resource`。礼装目录增删后还需运行本文的选项生成命令，使原生列表与当前目录一致。

`tests/test_support_ce_candidates.py` 覆盖选项生成、Android 转换、同槽位 OR、跨槽位 AND、满破状态独立及单选兼容。`tests/component/test_support_ce_candidates_framework.py` 使用真实 MaaFramework 和内存控制器验证 case 合并及跨任务隔离，不操作模拟器。
