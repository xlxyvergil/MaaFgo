## 2026-10-25 固定槽位采集加速

实施方案：仅优化 `FormationIdentityReader`，不更改自动编队的换人/拖拽逻辑或个人库存扫描。继续复用 `NarrowFigures`（缺失身份回退 `servant_face`），按固定六槽建立低分辨率特征的批量粗筛，合并同一 ID 的灵基/灵衣后选择候选，再用原模板执行精匹配。粗筛分数不能直接发布身份，也不能复用个人库存或自动编队少候选时的判定阈值；保留当前页面/比例、空位、助战及身份分数/不同 ID 分差检查。

## 行为与范围

原生单场/连续出击创建任务会话 → 进本 → 可选 Chaldea 手动检查或自动编队及羁绊补齐 → 最终确认页只读三帧采集 → 发布六槽初始快照 → 按原流程点击开始。

采集器不会点击、拖拽、换位或更换从者/礼装。Chaldea 自身已有的编队行为保持原样。BBC 默认走原确认点击路径，不启动采集；从战斗界面直接启动原生战斗时没有初始快照，继续现有通用策略。

`进本-点击队伍确认` 保留为所有编队分支的汇合点，实际点击移至 `进本-实际点击队伍确认`。原生入口只在任务 Context 内把汇合点的 `next` 改为 `编队身份-采集`，不覆盖 Resource，不改 Chaldea 编队方式选项。

页面、模板或有效截图识别失败时会清除旧快照、输出 warning，并按无初始快照的通用策略继续；用户停止任务仍保持停止。个别槽位未知则允许发布快照并继续。职阶模板统一存放在 `resource/base/image/battle/职阶`，避免 `base`、`jp` 等资源包无法读取 `cn` 层素材。

## 识别依据

`agent/custom/formation_action.py` 的 `FormationIdentityReader` 复用现有六槽 `SLOT_ROIS`、缩放、空位统计、助战标记和 OpenCV 模板匹配。只接收显式图像，不调用旧 `_shot()` 的缓存兜底，也不运行编成操作。

1. 使用“配置变更”及开始按钮共同确认页面，检查图像与布局。
2. 每槽先判断空位，再判断助战；随后读取独立职阶证据。
3. 高置信度职阶用于前两帧的候选剪枝。职阶未知、无候选、身份分数/分差不足立即全库回退。
4. 第三帧始终全库复核，避免错误职阶永久排除真正身份。剪枝只减少部分帧的匹配量，最终耗时需实测。
5. 同一从者 ID 的多个灵基/灵衣模板先取最高分，再比较不同 ID 的分差。不能把同名作为相同 ID，也不能把不同位置合并成一个成员。
6. 三帧身份/空位状态与助战属性一致才接受结果；冲突槽位降为未知。职阶不一致则清除职阶结论；身份与视觉职阶矛盾时保留可靠身份、清除矛盾职阶。

候选缓存只保存本地静态资料和模板；按路径、文件大小和修改时间失效，最多保留两个索引。使用显式图片清单和既有命名规则，资源层按现有路径优先级处理。没有对应关系或存在归属冲突的图片不会参与确定身份。

默认使用现有 `NarrowFigures → 缺失 ID 使用 servant_face` 路径。备用目录先扫描文件信息，仅解码缺少主模板的 ID，避免加载整份备用图库。完整头像可在离线评估时单独选用。

## 数据契约和生命周期

`battle/core/models.py` 新增不可变 `FormationSlot`、`InitialFormation`；`BattleState`、`ServantState` 和面卡 `owner_slot` 没有加入身份推断。

| 字段 | 含义 |
| --- | --- |

| `task_id`、`session_id`、`revision` | 根任务、随机会话令牌、采集代次 |
| `captured_at`、`captured_battle`、`source`、`calibration_id` | UTC 采集时间、所属场次、来源和标定记录 |

成员键为 `(session_id, revision, slot)`，同 ID 的本地从者与助战仍是不同位置实例。

`battle/runtime/formation_session.py` 使用带锁的会话注册表保存快照。所有读写校验根任务 ID、随机令牌和采集代次；子任务仅继承令牌，不通过 `attach` 回传快照。

- 新原生入口开始新会话；连续出击外层创建一次，`battle_count=1` 内部单场调度复用该外层会话。
- 每次采集先撤销旧快照，再提交当前采样结果。采集失败会丢弃旧版本并允许无快照继续；停止或过期回调不得重新发布旧版本。
- 连续出击每场从外层会话读取不可变初始快照，重新经过确认页则采集新版本。
- `repeat` 的 `finally`、Tasker 完成/失败及停止监听负责清理；进程重启没有内存结果可继承。
- Runtime 通过 `initial_formation` 接收快照；`initial_formation_reused` 表示本场未重新采集。原时间、初始位置不会被上一场的换人/退场覆盖。
- 连续出击可能重新选择助战，复用快照中的助战没有在本场重新确认。初始快照从来不表示当前回合前排，也不能直接用于面卡归属或从者专属策略。

## 标定入口与真实截图评估

开发配置放在 `自动编队.json` 的 `编队身份-采集.attach.calibration`，没有新增用户配置界面。参数由 `FormationCalibration.parse()` 校验：

- `verified`、`calibration_id`：只有完成真实样本评估后才能设置为已验证，并指向可追溯的记录。
- `template_family`：`NarrowFigures`（沿用现有缺失时备用规则）或 `servant_face` 对照组。
- `identity_threshold`、`identity_margin`：必须由不同 ID 的真实分数分布标定，不沿用 `FACE_THRESHOLD=0.62`。
- `class_roi`：相对每个槽位左上角的图标 ROI。
- `class_templates`：视觉职阶 → 图片路径数组；路径相对于资源 image 根目录。
- `class_groups`：视觉职阶 → 目录职阶数组。只配置有证据的对应关系，尤其不能直接猜测 `loreGrandCaster`、`beast`、`unBeast` 的归并。
- `class_threshold`、`class_margin`：职阶高置信度接受条件。

真实样本清单格式为 `{"samples": [...]}`。每个正样本包含 `id`、`source`、`expected_page: true`、三个不同原始文件的 `frames` 路径，以及按 1–6 排列的 `slots` 标注。占用槽至少标注 `servant_id`，空位标注 `status: "empty"`；推荐补充 `class_id`、`is_support`。负样本可只有一张图，使用 `expected_page: false`。

```powershell
install-mxu/python/python.exe -B -X utf8 tools/evaluate_formation_identity.py --manifest path/to/samples.json --calibration path/to/calibration.json --output path/to/report.json
```

路径相对于清单所在目录。工具只读图像，不连接设备。输出原图 SHA-256、逐帧/合并结果、错误/未知统计、初始化和匹配耗时。离线耗时不包含设备、Agent 或 Pipeline 等待。退出码 0 仅表示清单中未记录错误，不代表完整识别验收。

必须分离标定样本与验收样本，覆盖六槽、空位、助战、同名/同 ID、变体、相似头像和各种职阶；同时报告未知率，不能以全部未知换取“零误识别”。单张截图不得复制为三帧证据。

## 2026-11-01 编队采集资源层修复

用户日志实际加载 `base + jp`，但任务覆盖将 `资源包配置.attach.resource_package` 写成 `cn`。助战／进本由框架按加载层匹配成功；编队采集自行按任务标记取图，可能优先读取国服“配置变更”和开始按钮，在从者匹配前报 `not_on_formation_confirmation`，随后缺少战斗技能所需的身份候选。

编队路径选择改为优先使用资源包声明的 `loaded_resource_package`，与现有助战逻辑一致；仅旧资源包没有实际加载标记时兼容旧 `resource_package`。非法实际标记明确报错，国服仍逐文件回退 base。该公共路径同时用于自动编队、手动编队检查、原生初始编队采集及继承它的羁绊补齐，不调整匹配阈值或跳过页面安全检查。

增加实际资源层、搜索目录及页面模板路径日志；页面校验失败记录“配置变更”“开始任务”“战斗开始”各自分数与0.8阈值。离线回归应覆盖任务标记与实际层相反的双向情况、旧资源兼容、逐文件回退和非法标记拒绝；合成页面只用于流程验证，不代表用户现场截图已复现。

验证结果：36项编队单元测试、15项真实框架／助战资源选择测试均通过。新增回归在两套不同按钮模板间制造国日服标记冲突，检查最终文件路径并实际匹配合成编队页，六槽身份均成功采集；另验证失败日志含完整路径与分数。未连接用户设备，未声称已复现该用户原始截图。

同类代码排查发现整理礼物盒、强化从者及白纸化地球导航也直接读取旧任务标记，现与编队、助战统一调用 `agent/custom/resource_package.py`。公共函数优先实际加载层，旧包无标记时按旧选项解析；不改变各模块既有模板目录和逐文件回退。个人库存继承编队路径、羁绊补齐复用编队执行器、御主礼装使用编队 `image_roots`，均随公共路径修复生效。战斗状态头像、合成指令卡、礼装等共用资源使用 base 有明确用途，未将其误改成国服专用目录。MXU及Android打包复制整个custom目录，公共模块随现有流程分发。

扩展检查后的回归：编队36项、资源入口23项、真实框架17项均通过（测试组间有重叠），静态检查通过。真实框架覆盖国日服加载顺序、旧任务标记覆盖、Context克隆后的层选择，以及编队采集和导航状态流；使用内存控制器，不操作设备。本地测试回执在 `.workbuddy/runtime/qq-no-skills-20261101/`。
