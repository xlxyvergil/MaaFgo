# 编队与战斗编辑器使用说明

编辑器随 Windows MXU 包提供，在浏览器中设置六人编队、礼装和固定回合打法，保存为现有 Chaldea 格式。文件写入本次安装目录的 `config/Battle`。

## 打开编辑器

以下入口共用同一服务：

- 双击软件根目录的 **打开编队编辑器.cmd**，无需先启动 MXU 或连接模拟器。
- 在 MXU 中运行 **编队与战斗编辑器**任务，选择“启动并打开”。旧 MXU 会沿用任务的设备连接流程，但该任务不操作游戏。
- 使用支持本地说明链接的 MXU 客户端时，可直接点击战斗任务或 Chaldea 选项说明中的 **启动编队与战斗编辑器**，由客户端打开本安装目录的 CMD，无需先连接模拟器。此能力需要重新编译并更新 MXU 客户端；旧客户端仍可双击 CMD。

启动器确认服务就绪后自动打开默认浏览器。再次运行会复用现有服务；**打开已启动的编辑器**仍使用 `http://127.0.0.1:18765/`，适合服务运行后重开网页。浏览器版 MXU WebUI 不运行电脑上的 CMD，安卓不显示这些桌面入口。

Windows MXU 安装包始终优先使用本安装目录的 `python/python.exe`，不需要额外安装系统 Python。若提示缺少随包 Python 或随包环境无法运行，请把完整 MXU 包重新解压到新目录，再双击包内的“打开编队编辑器.cmd”；不要单独复制 CMD 或混用其他版本的 Python 文件。

源码目录的 CMD 会依次检查项目的 `.venv`、`venv`、Python 3.12 的标准安装目录、Python 启动器和 PATH 中能实际运行的 Python，要求3.12或更高版本；Windows 商店的 Python 占位程序不会被当作有效环境。找不到环境时会直接说明安装或更新开发环境的步骤，解释器尚未启动时不会要求查看不存在的服务日志。普通使用优先选择完整 MXU 安装包；开发使用请按工程要求准备 Python 3.12 与依赖，安装后重新打开终端或启动脚本。

源码开发不强制创建虚拟环境：正常安装的系统 Python 配齐项目依赖即可启动，`.venv` 和 `venv` 只是可选的依赖隔离方式。系统重装后，旧系统盘上的 Python 不会自动恢复新系统的安装信息；请在新系统正常安装 Python 3.12，并在源码根目录的系统终端中执行：

```powershell
py -3.12 --version
py -3.12 -m pip install -r requirements.txt
.\打开编队编辑器.cmd --help
```

若开发工具内能运行、资源管理器双击却失败，请从资源管理器打开源码目录，在普通终端检查上述命令，并重新启动编辑器确认网页可打开。部分带文件虚拟化的开发工具会使用私有文件和注册表视图，工具内找到 Python 不代表桌面环境也能使用。旧虚拟环境还可能引用原系统的解释器路径；迁移时应先恢复系统 Python 和项目依赖，再决定是否重新创建虚拟环境。

关闭网页不会立即停止服务。新启动的 Maa task 服务在识别到 MXU 宿主时跟随其生命周期；识别不到时会明确提示采用独立模式。CMD 启动的服务在无页面心跳一小时后退出。复用已有服务会保留其原有模式，页面底部可查看。需要停止时，点击页面“停止服务”、在启动任务中选择“停止编辑服务”，或在软件目录执行：

```text
打开编队编辑器.cmd --stop
```

同机一次运行一个安装目录的编辑器。同目录的健康服务会复用；另一安装目录的兼容服务经过身份核验后会被正常关闭并替换，已接收的保存会先完成。无法确认占用者身份或退出超时会报错，不强杀进程。页面显示实际保存目录，旧页面未发送的修改应先导出；详见[启动与旧服务接管](编队编辑器启动与旧服务接管.md)。

## 编队与回合

冠位从者的礼装 2 是该从者唯一的羁绊礼装，无需选择卡面、等级或满破状态。直接在该格或详细属性中选择“使用 NP 50% 替换效果”“保留原始效果”或“不限制”；冠位助战会按此效果筛选。普通礼装与追加礼装仍独立选择和拖动，自动编队暂不修改冠位从者的礼装。

1. 从方案库新建队伍，或打开 `config/Battle` 中已有的文件。导入弹窗优先显示工程方案，也可识别编队截图或导入 Chaldea 分享；本地 Chaldea JSON 与 BBC 配置文件的导入按钮默认并排显示。
2. 在“编队配置”设置六个固定槽位，前排为 1–3，候补为 4–6。选择从者、助战类型、概念礼装和御主礼装。等级等未指定的筛选值保持不限制。
3. 在“回合逻辑”点击从者或御主技能图标，按点击顺序添加动作；需要我方目标时点击弹窗中的头像即可加入，换人仍需选择双方后确认。换人后，技能区和后续对象立即变为当前站位上的从者。
4. 每回合配置最多三个出卡意图，可混排宝具、Buster、Arts、Quick。留空部分以及实战未抽到的指定面卡由当前原生策略补齐。
5. 在“检查与保存”处理阻断问题，再保存或另存。保存成功后复制文件名，在原有“Chaldea 队伍导入”输入框填写即可调用。

原生自动战斗中，回合列表的“0 回合”和“1 个空回合”含义不同：

- **没有任何回合**：仅配置编队，战斗从首回合起使用通用自动战斗，按当前策略处理技能、可用宝具和普通卡。无需为了保存阵容而添加占位回合。
- **明确添加的空回合**：这一回合不释放技能或宝具，只按通用选卡规则选择普通指令卡。它仍占一个回合；后面的已配置回合不会提前执行。
- **固定回合全部执行完毕**：从下一个回合恢复通用自动战斗，包括自动技能与可用宝具。删除最后一个回合会恢复“未设置回合逻辑”。

BBC 战斗可读取仅编队、没有回合的方案，使用其通用战斗逻辑；BBC 无法等价表达纯空回合，转换时会提示改用原生自动战斗，不会悄悄改成自动释放技能和宝具。有明确技能、只留空出卡的回合仍按已有 BBC 转换处理。

### 方案库排序与收藏

方案库可按“修改时间”“创建时间”或“名称”排序，并切换升序、降序；默认按修改时间从新到旧排列。排序选择会记住，下次打开时继续使用。名称按队名排序，没有队名时使用文件名。

点击每行复制按钮左侧的“★”收藏方案，再点一次取消。收藏的方案会在搜索结果中优先置顶，同组内继续按当前排序排列。收藏保存在本安装目录的 `config/BattleEditor/library.json`，不会修改方案内容、修改时间或哈希。

创建时间优先使用文件系统提供的真实创建时间，覆盖保存时保留原记录；不能取得真实创建时间的平台会稳定记录“首次收录”时间并标明，不将文件属性变更时间当作创建时间。

### 常用队伍

点击右上角“常用队伍”，在弹窗顶部选择冠位职介和具体副本，再按“高赞”或“最新”查询 Chaldea 公开队伍。每次最多加载 12 个队伍，点击列表底部“加载更多”继续查询；切换副本或排序会重新从第一页读取。弹窗在同一窗口尺寸下保持固定宽高，读取目录、加载、空列表和查询失败时均不会收缩；队伍列表在弹窗内部滚动。列表只展示编队、作者、点赞数、回合数等基础信息，图片复用编辑器本地资源。冠位从者下方按 1 主礼装、2 羁绊礼装、3 追加礼装显示，并标出羁绊礼装的 NP50% 或原始效果；鼠标悬停可查看礼装名称、等级与满破状态。羁绊礼装未指定卡面时，可使用该从者唯一的羁绊礼装图片展示，不会额外写入礼装要求。

点击队伍的“导入”，即可将其完整编队和回合行动载入独立草稿，随后在“检查与保存”中核对并保存至 `config/Battle`。导入会沿用现有能力检查，不会自动修改练度要求或保证实战通关。Chaldea 未公开实际使用次数，因此这里只提供高赞和最新排序。

查询与导入需要联网，失败时可重试；加载更多失败会保留已经显示的队伍。该功能无需安装额外依赖或下载 Chaldea 客户端，仅随桌面编辑器提供，不进入安卓包。

### 全局高级策略

在“回合逻辑”页的“动作属性与高级出卡”下方展开“全局高级策略”，可设置补牌预设、开局等待关键牌、补牌策略 JSON、最大战斗回合和自动补放从者技能。这些设置对整场战斗生效，没有设置回合或编队时也可编辑。默认收起，统一默认值为：**平衡补牌、不等待关键牌、自动补放从者技能、最多 40 回合**。

所有原生自动战斗任务最下面的“高级策略”决定使用哪一份配置：

- **默认**：直接使用上述统一默认值，不读取手动设置或方案里的全局高级策略。
- **使用编辑器/chaldea配置**：读取当前使用方案保存的全局高级策略；老方案没有这些字段时使用统一默认值。
- **手动**：展开 MXU 中的策略选项，以这里的设置为准。

方案中明确安排的技能、宝具、普通卡及其顺序始终优先；补牌预设只填充自动空位与未抽到的指定面卡。“自动补放从者技能”只在当前没有固定回合方案时使用，关闭它不会取消明确安排的技能。

开局等牌适用于从原计划首回合开始的新战斗。开启后需要明确设置目标从者或当前前排槽位、所需牌色和最多等待回合；等待期间只普攻，不推进原计划。没有回合方案时会跳过等待，继续通用战斗。从战斗中途启动时应保持关闭。

保存、另存、草稿和 JSON 导出会保留全局策略；打开老方案只展示默认值，实际修改策略后才新增扩展字段。该字段属于 MaaFGO 的 `maaAdvancedStrategy` 扩展，上游 Chaldea 的模拟参数 `options` 不会直接改变原生选卡。具体默认、字段及兼容规则见[高级策略实施方案](原生战斗高级策略实施方案.md)。

检查会提示六槽中重复的自有从者，同一从者只能安排一位自有成员；需要双同人阵容时将另一位设为好友/NPC助战。不同职阶或版本的独立从者不会仅因同名被判重复。队伍未设置助战时会给出提醒，特殊关卡或有意不带助战可以忽略，仍允许保存；点击提示的“定位”可回到编队调整。

编队COST超过当前设置的上限时，“问题与能力提示”会列出当前值、上限及超出量，仍允许保存。点击该提示可查看COST详情或修改上限；调整编队、礼装或上限后提醒立即更新。部分COST未知时，只在已知小计已超过上限时提示“至少超出”，不猜测未知部分。

配置了至少两个回合时，检查还会提醒实际前三回合中未安排宝具的回合，可点击定位核对，仍允许保存。普通卡及默认补齐不算宝具；宝具放在第2或第3个出卡位同样算已安排。少于三回合只检查已有回合，不推测后续回合；末尾只有技能、由默认选卡结束的回合也计入检查。该提醒检查方案安排，不保证实战宝具一定可用。

导入已有命名的方案，保存时默认继承原文件名；上传 JSON 优先保留上传文件名，只有队名的分享方案使用队名。该名称随编辑草稿保留。未命名的新方案仍默认以“来源_初始前排三名从者”命名，例如 `local_阿拉什_阿尔托莉雅·潘德拉贡_齐格飞.json`；Chaldea 分享和 BBC 配置的未命名方案分别使用 `chaldea`、`bbc` 前缀。名称可手动修改，不改变方案标题。

保存目标已经存在时，会单独弹出“是否替换原文件？”确认，显示实际文件名和路径；取消不会改动正式文件，也可选择“修改文件名”另存。确认替换后会备份旧文件，并检查原文件哈希；被其他窗口修改时会阻止覆盖，保留当前编辑内容。上传的外部文件只会保存到当前安装的 `config/Battle`，不会写回上传来源目录。按 Ctrl+Shift+S 明确另存时，默认沿用原名并在重名时追加短随机后缀。

回合按整场战斗累计推进，不按清波结果自动重排。页面是计划编辑器，不进行伤害模拟。技能冷却、识别或实际战况仍可能导致跳过技能或中止，首次使用新打法时请观察一场。

### 从 BBC 配置导入

在“导入”弹窗点击 Chaldea 文件按钮右侧的“导入 BBC 配置”，选择 BBC `settings` 中的单个 JSON 文件（最大 3 MiB）。转换在本机进行，无需联网、启动 BBC 或连接模拟器，MXU 包未安装 BBC 也可使用。

转换后先核对六个位置、助战、御主礼装、回合动作和转换提醒，再确认导入独立草稿。关闭预览或遇到无法转换的动作时，当前方案保持不变；导入不覆盖 BBC 原文件，也不直接写入正式方案。生成的数据与现有 Chaldea 战斗方案共用格式和检查流程；BBC 文件名、来源指纹与转换提醒随数据保留，转换提醒在“检查与保存”中也会持续显示，正式保存后重开仍可核对。

没有固定回合的BBC配置会保留零回合，交给通用自动战斗。可转换仇凛S2改色、普雷拉蒂和莉莉丝的已支持选项，以及能够唯一确认的攻击后自然退场递补；后续行动保留从者实例校验。助战的多个候选、旧版技能等级和满破默认值按BBC实际规则转换；冠位及羁绊礼装NP50／初始效果在核对界面单独显示。BB迪拜专属菜单、动态分支等尚不能等价表达的配置仍会明确拒绝，不会忽略指令后导入。

BBC 的脚本模式包含比固定回合计划更多的行为。能等价表达的设置会自动转换；不能等价的内容会给出明确说明。具体范围与限制见 [BBC 配置转换说明](BBC配置转Chaldea本地队伍.md)，导入后仍需检查当前游戏中的御主礼装与编队条件。

### 导出编队与战斗一图流

在“检查与保存”右侧点击“导出一图流”，预览后下载 PNG，浏览器支持时也可复制图片。图片包含六人编队、助战、概念礼装、养成要求、御主礼装和逐回合行动；技能带头像、图标与目标，换人后按当时的站位显示，宝具、普通卡与默认补卡位置按顺序保留。助战同一礼装槽的多个候选以“或”逐项展示。

导出的是当前编辑内容，无需先保存正式文件。尚有阻断问题时仍可导出草稿，图片页眉会标注检查状态；导出不会改变方案或绕过正式保存检查。图标加载失败时保留文字说明并提示。

图片页眉的定位码和底部全部回导码用于恢复完整 Chaldea 方案，包括回合、技能目标、换人、养成要求、缺省值和未知字段。分享时推荐发送原始 PNG，并保留整张图片；适度缩放或 JPEG/WebP 压缩也可尝试识别，但严重压缩、裁切或缺码会明确报错，不猜测缺失动作。

图片最底部显示 MaaFGO 图标、项目地址 `https://github.com/xlxyvergil/MaaFgo` 和“B站搜索：是kumi啦”，方便分享后寻找项目与作者。图标随编辑器离线提供，品牌页脚位于全部回导码之后。

图片固定宽1200像素，单边不超过12000像素、总像素不超过2000万，PNG 不超过16 MiB；内容或回导数据过多时会提示拆分方案或分享 JSON，不会截断导出。文字区不会自动加入本地保存路径或编辑器会话信息；回导码包含方案对象中的完整数据。

### 从截图或一图流导入

在“导入”弹窗上传或拖入图片，也可点击“粘贴图片”，或直接在弹窗任意位置按 Ctrl+V（包括分享链接输入框）。普通文本粘贴仍按输入框处理。浏览器不允许读取剪贴板时，可以直接按 Ctrl+V 或上传文件。

图片会自动区分三类，先定位本工具回导码或 Chaldea 页脚，再进入对应识别流程：

- **本工具一图流**：在本机校验回导标记，展示完整编队与回合摘要；缺失、损坏、混入多份方案或不支持版本的标记会拒绝导入。
- **Chaldea 分享图**：通过底部 `Created by Chaldea App` 或 `chaldea.center/laplace` 定位，定向识别附近的 `Team 数字`，再联网读取对应公开队伍。预览会显示识别到的 Team ID 和分享链接，确认前请核对。没有发布过的队伍可能没有 Team ID；找不到 ID、读数不清晰、多个 ID 冲突或队伍无法获取时，会说明原因，不从伤害或关卡数字猜测配置。原图只在本机处理，联网仅查询队伍 ID；获取的是该 ID 对应的线上配置。
- **游戏编队确认页**：沿用从者、礼装模板识别，可在预览中手动更正，不生成战斗回合。

三类图片均在核对并确认后建立独立草稿；关闭预览不应用结果。本工具一图流和游戏截图可离线处理，Chaldea 图片获取线上配置需要联网。

支持 PNG、JPG/JPEG、WebP 静态图片，最大16 MiB、2000万像素、单边30000像素；游戏截图请使用完整的六人编队确认页，保留六个槽位和礼装区域。不同分辨率、宽屏和额外黑边可自动定位；严重裁切、遮挡或模糊的图片可能无法识别。图片只在本机处理，无需模拟器；Chaldea 分享图仅在读取队伍配置时联网。上传的原图不会另存到方案文件中。

识别完成后先核对六个位置，可搜索更换从者、礼装，指定助战或取消某位置要求，再点击“确认并导入编队草稿”。低分项目显示未识别，不自动猜测；未知从者仅能作为好友助战单独保留礼装，其他位置需先补选从者。礼装只识别工程已经收录的正式模板。导入创建独立草稿，原方案保留；关闭弹窗不应用预览，正式保存仍需通过方案检查。

截图只提供从者、普通礼装和助战要求，不识别等级、技能、宝具、冠位、满破或御主礼装；这些值保持未指定，导入后请自行补充。截图不会生成战斗回合。

### 六人编队界面

六个位置始终在同一行，从左到右为三个前排、三个候补。每张卡从上到下依次显示从者头像、星级/等级/宝具/主动技能等级、概念礼装。好友与 NPC 助战标记在头像右上角，以放大的图标和文字显示。窄窗口可在编队区域内横向滚动。

编队下方右侧显示 `TOTAL COST 已配置值 / 上限`，从者、礼装选择或移除后自动更新；助战整槽不计费，空位与“不要求礼装”只代表未配置，不推测游戏中实际携带内容。点击COST可修改上限，默认117，支持1–300的整数并记住当前浏览器的设置；与“自动羁绊最大化”共用上限，不写入战斗方案。超过上限时突出显示。资料缺失或自有冠位的实际COST无法确定时显示问号，并可点击查看原因，以免把普通礼装合计误当冠位折扣后的值。

选择从者时，星级行右侧可切换排序依据和升序/降序，默认“ID顺、升序”；ID指内部从者ID，也可改用图鉴编号或星级排序。职阶、星级和排序设置会记住上次选择，关闭后重开或刷新页面仍会恢复；选择“全部”或清除筛选会更新记忆。这些偏好仅保存在当前浏览器，不改变战斗方案，也不影响礼装筛选。

选择玛修·基列莱特时，会继续打开形态窗口，可选择初期三星、第一部四星、奥特瑙斯初期／黑枪强化／修复后，以及帕拉丁五星。每项同时显示星级、COST、三个技能与宝具，点击后一起应用；关闭窗口不改编队，返回列表保留筛选。已选马修可在属性区点击“切换马修形态”，等级、技能等级与礼装保留，可撤销。帕拉丁自有从者按16 COST计算，其他形态为0，好友／NPC助战仍不计COST。列表中同一个马修可在三星、四星、五星筛选下找到。

马修形态沿用 Chaldea 的 `svtId=800100`、`limitCount`、`skillIds`、`tdId`，导入已有方案会读取这些字段还原显示；显式技能与宝具优先保留，查看不会自动改写缺失字段。战斗和编队识别仍把所有马修外观视为同一从者，按配置的站位释放技能；不会自动替玩家切换游戏内形态。详细对应及来源见[马修多形态兼容说明](编队编辑器马修多形态兼容说明.md)。

从者、概念礼装与御主礼装选择窗口始终保持当前窗口允许的最大尺寸。筛选后只有一项或没有结果时也不收缩；标题和底部分页保持原位，中间内容可滚动，高级筛选展开不会撑大弹窗。

从者与概念礼装列表的星级以金黄色单独显示在对应图片下方；文字区继续显示职阶／礼装分类等信息。0星使用空心星并标注“0星”，资料缺失时显示未知占位。

新建方案默认使用 Lv.10 决战用迦勒底制服。第1位空槽显示“默认助战”，从这里选入从者后自动设为好友助战，其他空槽默认自有；成员类型仍可手动调整。队内已有其他助战时不会再自动增加助战，更换已选从者保留原成员类型。新队伍在正式保存前清空第1位再选仍使用此默认，草稿恢复会记住新队伍设置；打开、导入、复制已有方案不会额外设助战。空槽标记不代表已选从者，也不计COST；羁绊自动补齐会优先为它预留第1位。

好友助战可以只要求礼装，不指定从者。新队伍默认助战空槽可直接选择礼装；其他空槽可在槽位详情点击“设为助战（仅要求礼装）”。已选好友助战也可“清除从者要求，仅保留礼装”，保留礼装及冠位相关设置。该位置显示“助战（仅要求礼装）”，助战COST仍为0；需要指定从者时点击头像补选。槽位右上角叉号仍清空整位要求，礼装叉号只清除对应礼装。

仅要求礼装的助战身份未知，战斗编辑不提供该位置的主动技能、临时就绪、宝具或指定普通卡；默认普通卡补齐仍可用。该位置可作为按站位选定的我方技能目标或换人对象，换人后按当时阵容重新判断可用动作。原方案若已有引用该未知身份位置的技能、宝具或指定色卡，动作保留并在检查页提示修正，不能当作已知从者执行。

编队下方的紧凑御主礼装卡显示衣服图标、服装图片、名称及等级，点击卡内“更换”选择其他服装；游戏内仍需穿戴相同服装。导入已有方案时保持其原始御主服设置。

回合页的宝具按钮显示本地合成的完整卡面。可切换日服/国服卡面文字，此设置只影响预览；宝具与已记录灵基优先按方案资料匹配，未指定灵基时使用默认原生卡面。素材缺失或形态无法确认时会显示名称和提示，仍可安排宝具，不会自动换用其他区服或其他从者图片。

“宝具与色卡”及高级选卡区域同样显示对应从者的完整卡图。拖起已安排的卡片，放到同组另一张卡或默认补齐空位上即可调整出卡顺序，可撤销；只有一张宝具时，也可移到第2或第3位，前面按当前默认选卡策略选择普通卡。左右箭头同样支持移入空位。卡图按该回合实际前排和所选颜色显示，点卡片或“编辑出卡 / 目标”仍可修改详情。后续添加宝具或普通卡会优先填入默认空位。

出卡顺序使用左右箭头调整前后位置；删除按钮在每张已选卡右上角，以较大的红色叉号显示。高级出卡区域在窄窗口保持横向排列，可横向滚动。调整顺序或删除卡片时会退出当前单张卡编辑，避免后续更新到变更前的位置。

空槽首次选择从者时，主动技能预设为 10/10/10，五个追加技能预设为 0（不要求），与当前助战 task 一致。这些是可编辑配置，不会替你强化从者，也不代表 NPC 的实际等级。已有方案保留原值；需要时点击属性区“补齐技能默认值”，仅补空项，原等级和显式 0 不变，可撤销。

导入窗口可点击“从 config/Battle 选择”，直接搜索当前 MaaFGO 实例的战斗文件，不必在系统文件选择器里寻找目录；页面会显示实际路径。导入后进入独立草稿，保存沿用原文件名，替换前会再次确认。其他位置的 JSON 仍可用“选择本地 Chaldea JSON”导入。

从头像、从者信息或拖动把手拖起成员卡，超过少量移动距离后整卡会跟随鼠标，目标槽位高亮；放开即可交换整位从者与礼装。从礼装区域拖起时只有该张礼装跟随鼠标，放到另一处礼装格即可调整礼装位置。原位或编队外放开不交换，按 Escape 可取消。点击头像和礼装的原有选择操作保留。

选择从者时，点击“高级筛选 [展开]”可按阵营、善恶属性、性别特性、天地人星兽、羁绊特性、宝具类型与宝具色卡继续筛选。所有条件与搜索/职阶/星级共同生效，多选的羁绊特性需同时满足。收起面板仍保留条件，标题显示已启用数量，点击“清除高级”可保留基础筛选。

默认筛选基础资料；勾选“包含灵基 / 灵衣条件”可查找部分形态才符合的从者，结果会标记。宝具类型与色卡按同一条宝具资料匹配。涉及变体时仍需核对实际灵基、灵衣和宝具状态；这里的筛选不会替你切换从者形态，也不会改写已有战斗配置。

- 点击头像更换从者。选择界面直接展示职阶图标与星级按钮，可与名称、编号和“仅持有”组合筛选。
- 点击已选从者卡片蓝色序号栏右上角的叉号，取消该位置的从者及附属礼装要求，显示“不要求此位置”。六槽编号保持，其他成员不会前移；这不要求卸下游戏内从者。技能、出卡和换人动作保留，有已有动作时请在回合页核对。支持一次撤销/重做，草稿自动保存。
- 点击卡片中部信息或位置序号，定位到下方属性面板；主动与追加技能等级旁显示对应技能图标。未提供准确资料的技能显示未知占位。

- 拖动礼装图片、名称或其余按钮区域，只交换两处具体礼装要求，等级、满破、附加属性及全部候选随该礼装槽整组移动，从者及其余礼装保持。可拖到已有从者的空礼装格，原位置变为“不要求礼装”；不能放到没有从者的空卡。冠位三个礼装格可分别拖动，也可在同一冠位内部交换；带多候选的整组只接受支持候选筛选的助战礼装槽。点击礼装仍打开选择器，右上角叉号只清除该格要求。每次有效拖放均可一次撤销，草稿自动保存。

### 礼装星级、来源与高级筛选

“星级”位于选择器最上方的快捷区，其下是“来源”，可选择通常、活动召唤、活动报酬、纪念配布、工坊等来源。普通、羁绊、巧克力等礼装“类型”位于高级筛选中。搜索同时支持礼装名称、编号，以及羁绊礼装对应从者的姓名、别名和 ID。“羁绊礼装”是一种类型，“羁绊获取”是增加羁绊经验的效果，两者独立。

展开“高级筛选”可设置类型、初始 NP 范围（含 ≥30/50/80/100% 快捷项）、COST 范围、纯 ATK/纯 HP 等属性倾向，以及 NP、卡色、宝具威力、特攻、暴击、生存、辅助与刷本收益等效果。多个效果可选“全部满足”或“任一满足”，仍与快捷筛选、搜索和库存条件取交集。初始 NP 阈值只计无条件开场充能，不把每回合、退场、概率或其他条件充能算入；条件效果默认不参与匹配，勾选“包含有触发条件的效果”后会明确标记。资料未知不会当作零值。收起后保留条件，标题计数包含类型；“清除高级”只清类型及高级条件，保留顶部星级与来源。

“未满破效果/满破效果”仅决定筛选和摘要使用的数值，不会修改方案的满破要求，也不代表库存中拥有满破礼装。实际满破条件仍在成员详细设置中指定。结果可按 ID、图鉴编号、星级或 COST 升降序排列；资料缺失的项排在末尾。

礼装卡片展示小型效果摘要，点击卡片直接选择；右下角信息按钮可查看基础/满破数值、作用对象、触发条件和日服原始完整说明。返回筛选保留当前条件。效果资料随程序离线提供，活动效果仍以对应活动与游戏内说明为准，不会额外下载或增加工程无法识别的礼装图片。

页面默认使用蓝白金配色，可从顶部切换深色。编队卡的职阶图标按星级显示原生铜色（1–2 星）、银色（3 星）或金色（4–5 星）；筛选器使用金色职阶图标。0 星和特殊职阶按准确资源映射处理，缺失时有明确回退。

### 助战礼装的多个候选

普通助战的主礼装槽可配置最多三个候选，命中其中任意一个即可。冠位助战的普通礼装（第1格）与追加礼装（第3格）可分别配置最多三个候选；同一格按“或”匹配，两个格的要求都要满足。第2格羁绊礼装沿用羁绊效果筛选。自有从者的礼装使用单张首选。

先在成员卡底部选择首选，再点击该成员进入下方详细设置。在“概念礼装”中，每个真实礼装槽横向显示“候选1（首选）”“候选2（或）”“候选3（或）”三个模块，依次添加其余候选；不能跳过前一个空候选。同一格不能重复添加同一礼装。

每个候选独立设置“满破”“非满破”或“不限制”，追加候选不会继承首选的满破要求。需要同一礼装不限满破时，保留一项并选择“不限制”即可。等级仅用于记录与方案检查，当前助战筛选不会据此识别礼装等级，也不会提升游戏中的礼装等级。

成员卡保持原有礼装区域大小，以呼吸淡入淡出轮播同一格的候选，并显示 `1/3` 等序号。轮播只影响展示；点击卡面礼装仍编辑首选。页面隐藏或拖动时暂停轮播；浏览器开启减少动态效果时静态显示首选。

详细设置中各候选右上角的叉号只移除该候选；删除首选后，其余候选按顺序前移，原候选2成为新首选。点击该格“清除全部”或成员卡礼装右上角的叉号会清除整组要求。修改可撤销，并随草稿保存。

多候选使用 MaaFGO 扩展字段保存，原有 Chaldea 单礼装方案和旧版 `ceId` 方案可继续导入。外部 Chaldea 标准只识别首选；需要完整保留多个候选时，请保存本工具 JSON 或导出本工具一图流。导入预览会标明同槽的“或”候选，确认时请一并核对各候选的满破要求。

### 自动羁绊最大化

点击编队下方、御主礼装右侧的“自动羁绊最大化”，在弹窗中确认COST上限、基础羁绊、补齐优先星级和本地持有库范围，再点击执行。默认COST117、基础羁绊1200、优先5星，保留现有从者与礼装，只补空位；无助战时默认预留最后一个空槽，最多配置五名自有从者。已有助战和冠位三礼装不会替换。需要调整普通已有礼装时，显式勾选“允许更换已有礼装”。高级选项可排除从者，并限制只使用本地已确认满破的礼装。

排除从者列表以头像、名称、职介图标与文字、头像下方的黄色星级及图鉴编号显示，可整卡点击或用复选框勾选，选中后突出显示。搜索支持中文／日文名称、别名、ID和图鉴编号，切换搜索保留已选项；上方已选标签带职介，点击叉号只取消对应从者的排除。

点击“执行羁绊最大化”时，会在当前浏览器记住基础羁绊、优先星级、持有范围、礼装更换／满破限制、助战槽位和排除从者；即使本次规划失败也会保存，关闭弹窗或重新启动编辑器后自动恢复。仅修改后取消不会覆盖上次执行设置。COST上限在执行时同步到编队页面并记住，打开时沿用编队当前上限。当前编队已有助战时优先沿用；记住的助战槽位被占用时改用空槽。冠位的“已有编队实际COST”需每次重新填写，不复用另一支队伍的数值。这些设置不写入战斗方案。

“仅持有”读取本工程已完成扫描的本地库，不会实时扫描模拟器；库缺失或不完整时先修复扫描，或明确取消相应限制后在工程支持的范围内规划。取消持有限制的结果需要自行核对持有，礼装仍限工程可识别范围；新配礼装如按满破效果计算，会记录满破要求。当前有冠位从者时，需输入游戏中当前实际COST，避免猜测冠位折扣。

执行成功后直接更新当前草稿，弹窗显示COST、羁绊估算和变更摘要；一次撤销即可完整恢复，随后仍需按原流程保存正式方案。失败、超时或规划期间方案已变化时，不应用结果。该功能复用工程现有星级优先与礼装搜索逻辑，只考虑常驻羁绊效果，得分是规划参考；不含助战礼装、活动加成、实时满羁绊状态及冠位特殊效果，不能保证数学上的全局最优。

### 像战斗界面一样编排技能

回合页显示三名当前前排的战斗头像，下方是三个技能和宝具卡，右侧为御主服与御主技能。这里显示本回合全部已排技能执行之后、攻击之前的阵容；下方选中旧步骤时，其详情会单独显示当时阵容。

1. 点击就绪技能。有我方单体目标时，点击弹窗中的当前前排头像即加入技能队列并关闭弹窗，从者技能与御主技能一致。资料未知时可点击头像指定目标，或点击“不指定我方目标”直接加入；若还需设置敌方目标，先调整敌方选项再点头像或“不指定”。自用、全体或自动作用技能直接加入。取消、关闭或按 Escape 不会添加步骤。不能选自己的技能会禁用施法者，空槽也不可选；换人仍需选择前排和候补后确认。
2. 用过的技能变灰并显示基础 CD，再次左键不会重复加入。需要编排减 CD、再次使用等打法时，右键图标选择“在编辑器中置为就绪”，或用技能名旁的时钟按钮；之后可再点击同一技能，已有步骤保留，可连续编排多次。已手动就绪的技能再打开菜单时，仅显示“取消就绪”，点击只撤回这个技能的临时标记，不删除已有步骤或影响其他技能；自然就绪状态不受影响。点击菜单外或按 Escape 可直接关闭菜单。同回合可同时标记多个技能；成功使用其中一个只消耗它本次的就绪标记，其余保持可用。取消目标选择不消耗标记，加入宝具也不会清除其他技能的标记。
3. CD 随全局回合自动递减，候补暂停；换人时跟随实际编队成员，同名助战单独计算。未填技能等级时显示真实 CD 范围，资料缺失显示未知。右键就绪只是一次临时许可；切回合、换人、撤销/重做、切换方案或从其他位置修改计划后，清除标记并重新按步骤推算。
4. 下方技能队列按点击顺序排列。拖动把手或点击上下箭头调整顺序，X 删除，复制按钮追加副本；可通过顶部撤销或 `Ctrl+Z` 恢复。修改后会重算阵容与 CD，并自动同步草稿。
5. 单体敌方技能默认“敌方 1 · 左侧”。点击下方该步骤，在展开的属性中修改该技能的敌方目标。切敌将在该技能前执行并确认；目标确认失败时停止该次技能执行。攻击组可另设目标，未指定时沿用原生默认选敌；技能击倒原攻击目标时，普通攻击继续沿用当前有效选怪。
6. 点击御主服可以直接更换服装和等级。换人服的技能 3 会弹出选择框，从当前前排与候补各选一名确认；换入者的技能立即可编排。更换御主服后检查已有御主技能和换人步骤的含义。
7. 点击宝具卡，把宝具加入下方“宝具与色卡”出卡组。宝具和 B/A/Q 共最多三项，同一当前前排宝具每回合最多一次。点击“编辑出卡 / 目标”配置普通面卡、顺序与高级改色。
   已安排宝具与普通卡右上角的叉号可移除这一张出卡，后续卡片依次左移，末尾由默认选卡补齐。删除宝具后可从上方重新安排；技能步骤和敌方目标保留，操作可撤销。

宝具在回合末与面卡一起出卡，技能步骤始终在它们之前；不能把技能拖到攻击之后。页面不模拟 NP 条，也不自动推算追加技能5、技能/宝具减 CD、技能封印或变身等效果。基础 CD 是编排提示，右键不会给游戏发送“重置 CD”指令；实际技能可用性仍由战斗识别决定。

### 从者退场与递补

在回合页右键点击当前前排头像，选择“从者退场”，即可将退场标记加入技能队列。它与技能一样支持拖动排序、上下移动和叉号删除，也可撤销。预览中，该从者移至队伍末尾，首位有效候补递补到原位置；可继续为递补者安排技能与出卡。退场者不能再通过换人或后续递补回到前排。

退场标记用于声明游戏中实际发生的自然退场，不会主动让从者退场。技能立即导致退场时，将标记排在该技能之后；宝具导致的退场发生在攻击阶段，请在下一回合开头添加标记。原生战斗会等待递补者稳定进场、确认身份后继续执行；实际没有退场时不会强行向原位置释放后续技能。

已有技能和出卡会记住原从者。移动或删除退场标记后，如果动作仍指向已经退场、尚未进场或站位不符的从者，“检查与保存”会给出红色错误并阻止正式保存。请删除原动作，为当前前排重新添加，或在动作属性中明确重选施术者。草稿与保真下载仍可保留未完成的编辑。

没有可用候补、候补未指定从者，或退场者与递补者身份相同而无法可靠确认时，检查同样会阻止正式保存。退场方案请使用原生自动战斗；BBC 不支持此标记，转换会明确报错。本工具的 JSON 和分享一图流可完整保留退场与动作身份数据。

列表改动立即生效，约一秒后自动保存磁盘草稿；只有点击“保存方案”才写入供战斗调用的正式文件。

“检查与保存”的打法摘要用小头像、技能图标和宝具／色卡缩略图辅助阅读：技能按“施术者 使用技能 → 目标”展示，御主技能显示御主礼装图标，换人显示换出与换入双方；攻击按已配置顺序显示从者和卡色。头像与名称按每一步执行时的阵容解析，换人后会同步变化。未指定出卡仍提示默认策略补齐，图片或元数据缺失时保留文字说明。

龙之炉心等技能会改变面卡颜色。普通面卡默认自动选取基础牌组中未重复的同色索引；需要记录改色时，展开“技能改色 / 指定牌组卡”，明确选择第 1–5 张牌组卡，再设置实际颜色。导入的合法改色记录会保留并提示核对。牌组索引用于保持 Chaldea 数据结构；当前战斗执行仍按从者与颜色选卡，不能精确锁定屏幕上的同人同色卡。

## 数据与恢复

- 正式队伍：`config/Battle/*.json`。
- 编辑草稿、历史备份和服务日志：`config/BattleEditor`。
- 自动草稿和正式保存是两种状态；只有正式保存的队伍文件可供战斗任务导入。
- 修改已有文件时检查原始哈希；文件已被其他窗口改动会提示冲突，不直接覆盖。
- 导入对象中的未知字段保留。当前执行器不支持的动作或特殊选项会阻断“可执行保存”；可保留草稿或下载原数据副本。

不要直接清理 `config/BattleEditor` 来解决保存问题，先保留草稿和日志。软件更新时保留整个 `config` 目录。

## 当前执行范围

支持当前前排技能、御主技能、普通三敌人目标、现有换人服、宝具和色卡混排。导入的 `delegate.tdTypeChanges` 与 `delegate.skillActSelectSelections` 已可由原生战斗按实际菜单依次执行；未配置对应字段时沿用固定默认项，具体从者、索引和验收范围见[特殊技能清单](特殊技能选项批量补全与日服实机验证方案.md)。冠位三礼装可以记录，但自动编队不会替冠位从者配置三张礼装。御主礼装也需在游戏内确认一致。

点击已支持的特殊技能会打开效果选择弹窗，例如太空伊什塔尔二技能的 Arts／Buster／Quick、库库尔坎的星数消耗选择。点击效果即继续安排；如果技能还需要我方目标，继续点击前排头像即可加入队列。中途取消不会留下半条动作。已安排的技能可在“动作属性与高级出卡”中修改效果，技能队列、打法摘要和分享一图流都会显示这次选择。

选项随技能动作一起复制、删除和排序，换人后的技能按当时的从者解析。仅强化后才出现菜单的技能会依据所选技能版本显示；导入的未知或无法可靠配对的数据保留并给出检查提示。未设置特殊选择的旧方案仍使用自动战斗原有默认行为。明确选择消耗星数等有条件的选项时，请确保游戏内满足条件；原生执行器不会在条件不足时擅自换成另一个选项。

配置了特殊技能选项的方案请使用原生自动战斗。BBC 无法无损执行这两类选择队列，转换时会明确提示，避免丢掉选项后继续战斗。HP / NP 条件分支、逐波次触发和 BBC 扩展动作仍不在当前执行范围。

## 开发与构建

开发目录构建页面：

```text
npm --prefix web/battle-editor ci
npm --prefix web/battle-editor run build
python -X utf8 agent/battle_editor/launcher.py
```

发行包自带 Python 和构建产物，玩家不需要 Node 或全局 Python。Maa task 与 CMD 使用同一启动模块，服务只监听本机，日常编辑与保存可离线。

资源重建、字段契约、增量维护和验收命令见 [维护说明](HTML编队与战斗编辑器维护说明.md)。
