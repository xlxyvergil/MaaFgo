# BBC 配置转 Chaldea 本地队伍

## 编辑器文件导入

在“导入战斗方案”弹窗中，“导入 Chaldea JSON”和“导入 BBC 配置”默认并排显示。点击右侧 BBC 按钮，选择 BBC `settings` 中的单个 JSON 文件（UTF-8，可带 BOM，最大 3 MiB）。

文件在本机转换，无需联网、启动 BBC 或连接模拟器。先展示六个位置的从者与礼装、助战、御主礼装、回合与动作数量、转换提示和方案检查；确认后才创建独立的 Chaldea 格式草稿，可继续编辑和保存。失败或关闭预览不切换当前方案，也不覆盖 BBC 原文件。首次正式保存的默认文件名前缀为 `bbc`。

转换后的 `_bbcSource` 保留来源文件名与内容指纹，`_conversionWarnings` 保留转换提醒。提醒在“检查与保存”中也会显示，正式保存后重开仍可核对；这些元数据不改变战斗执行。`_bbcWaveTurns` 只记录各波有效回合数，不是运行时的波次触发器。

## 原有批量转换任务

任务列表的“BBC 配置转 Chaldea 本地队伍”与编辑器共用转换器：

- “转换一个配置”：从本工程的 `BBchannel/settings` 选择一个队伍 JSON。
- “转换全部配置”：逐个处理该目录中的 JSON；无法可靠转换时记录文件名和原因，继续处理其他文件，最后汇总成功与跳过的数量。

任务直接生成 `config/Battle/bbc_*.json`，日志给出文件名。重复运行复用内容相同的结果，源文件变化则生成新指纹文件，不覆盖旧队伍。随后可在原有“Chaldea 队伍导入”输入框填写生成文件名。

## 自动转换范围

| BBC 配置 | Chaldea / 原生行为 |
| --- | --- |
| 六个 `servant_N_name` | 固定前排与候补槽位；未指定位置为 `null`，不新增要求 |
| `assistIdx`、`assistMode` | 正确标记好友助战；“仅礼装”不要求从者身份，不能为未知从者安排技能、宝具或指定普通卡 |
| `skillsLevel`、`NPlevel`、`servantLevel` | 有效的助战主动/追加技能、最低宝具和从者等级要求；0 保持不要求。BBC 缺省 `skillsLevel` 或旧值1要求10/10/10，旧值0、null不设技能门槛；不把助战门槛加到自有从者或仅礼装助战 |
| `assistEquip`、`fullEquip` | 助战礼装及同槽候选；1或省略要求全部候选满破，0不限制满破，不会变成“非满破” |
| 冠位助战、`jbType` | `grandSvt`；普通/羁绊/报酬礼装依次进入 `equip1/2/3`；NP50/初始效果写入 `classBoardData`，无需虚构羁绊礼装 ID |
| `master_equip` | 御主礼装 ID，包括二十八怪物、迦勒底学园制服；没有礼装且没有御主动作时可省略 |
| 技能 1–9、10–12 | 按原顺序生成从者或御主技能 |
| `[技能编号, 我方目标]` | 我方目标槽位 |
| `[12, 前排, 候补]` | 换人技能与 `delegate.replaceMemberIndexes`，后续技能/出卡按换人后的身份解析；支持连续记录多次换人 |
| `[13, 敌方位置]` | 1–3 号敌方目标，附到之后的技能与攻击，延续到本波后续回合；正确换算左右编号 |
| 仇凛负号S2、Prelati、Lilith | 按实际从者和技能位置转换特殊选项；详见下节，不把专属指令当作普通技能忽略 |
| 攻击后的 `replace` | 只有能唯一等价为自然退场及存活候补递补的映射才转换，保留初始编队与实例校验；任意复制、换位、删除候补或无后续回合的映射拒绝导入 |
| 每波多回合 | 裁掉 BBC 规则中的末尾空白编辑行后，展开为累计固定回合 |
| 未配置任何 `roundN_turns` | 保持 `actions: []`，使用原生通用自动战斗，不补造空白攻击回合 |
| `np` | 没有有效 `strategy` 时按原顺序生成宝具 |
| 固定选卡策略 | 保留宝具、单一从者/颜色普通卡及自动补卡位置，可以先普通卡后宝具；有效 `strategy` 优先于 `np` |

从者名字通过 BBC 三服资料中的 SN 确定身份；随包提供已核对的名字与无歧义别名映射，没有完整 BBC 安装也能离线使用。实际 BBC 资料存在时优先使用，再用随包映射补足缺失名字。普通卡牌组来自编辑器随包资料；不下载新头像、礼装或识别模板。

BBC 只给出助战礼装筛选，没有逐个指定自有从者礼装的字段。自有从者礼装、没有来源的养成值不会自动补造。`dropImage` 是掉落识别图片路径，不是队伍礼装。

## 特殊技能与自然退场

支持太空伊什塔尔（宇宙凛）的负号S2指令，例如 `[-2, 2]`、`[-5, 2]`。BBC按钮顺序为Quick／Arts／Buster，转换为 Chaldea 的 `tdTypeChanges` 数值3／1／2；上述两个例子均为Arts。必须与当前前排的真实从者和S2位置匹配，其他负号技能不会据此猜测。

`["Prelati", 技能号, "不替换"/"替换"]`、`["Lilith", 技能号, "不付与即死"/"付与即死"]` 转为对应技能与 `skillActSelectSelections` 的0／1。启用某类选项队列时，同类普通菜单动作也会逐项补入原生默认选项，避免后续选择错位；强化版本不明或不能确认菜单时明确拒绝。BB迪拜目前缺少对应原生菜单，仍不支持 `BBDubai` 指令。

BBC 的 `replace` 是攻击结束后按旧槽位快照同时赋值，不是御主换人。只有与一组唯一的自然退场顺序完全一致时，才在该次攻击后、下一回合技能前插入 `retire`。后续技能和指定卡片带原始从者实例 `actor`，避免编辑后误用已退场成员。此标记只等待并确认游戏中实际退场，不会主动杀死从者。最后一次固定攻击后没有后续回合的映射暂不导入，防止生成无法执行的退场确认。

## 助战候选礼装

普通助战的 `assistEquip` 外层各项是同一礼装槽的候选（OR），例如 `["A", "B", "C"]` 转为 `equip1` 的三个候选，不会误作冠位的三个槽。若普通助战写成 `[["A", "D"], "B"]`，BBC 实际只检测每个内层列表的第一项，因此只导入 A、B，并提示 D 未参与 BBC 实际检测。

冠位助战的外层三项分别对应普通、羁绊、报酬三个真实礼装槽，进入 `equip1/2/3`；各槽内的列表完整保留为候选（OR），不同槽的要求同时满足（AND）。每个真实槽最多三个候选，超过上限时报错，不截断。当前原生助战的羁绊槽使用效果筛选，若 BBC 配置了该槽的额外卡面候选，导入后会明确提示暂不支持并阻止正式保存；普通与报酬槽支持卡面候选。

Chaldea → BBC 转换时，BBC 的 `fullEquip` 是全局条件：所有候选均要求满破，或均不限制满破，可以保留；候选之间的满破要求不同，或明确要求非满破时，BBC 无法表达，会报错，避免改变筛选条件。原有单礼装结构保持兼容。

## 必须核对的差异

Chaldea → BBC 转换中，`actions` 缺失、`null` 或空数组表示未配置回合，不生成固定回合字段，由 BBC 自由战斗逻辑使用技能、可用宝具及默认普通卡。显式配置攻击回合、其中 `attacks` 缺失、`null` 或空数组，且该回合没有技能时，BBC 会把这个纯空回合忽略并启用自由战斗，无法保持“不用技能和宝具”的含义，因此转换会明确报错；请改用原生战斗。该回合已有技能、只将普通卡交给默认规则的配置仍可转换。

反向转换会正确生成御主换人指令 `[12, 前排1～3, 候补4～6]`，保留换出位置；不会使用代表专属技能的负号指令。末尾只有技能的回合会保留为技能加默认普通卡、无宝具的回合。带 `retire`／`actor` 身份校验、显式普通卡或 `isAuto` 占位混排、非空 `maaAdvancedStrategy` 的方案不能无损转为BBC，转换会在创建或覆盖文件之前明确拒绝；请使用原生战斗。旧纯宝具方案仍可转换。

BBC 按实际波次执行，原生计划按整场战斗累计回合执行。提前清波或多打一回合时，后续动作不会自动等待原 BBC 波次；每份转换结果都会提醒这一点。中间波次没有固定回合而后面仍有动作时，无法可靠确定等待时机，会拒绝直接导入。

多套普通卡优先策略、多个普通卡候选、暴击星阈值、波次额外选卡策略等没有完整的固定卡位等价物：转换器保留能确定的部分，给出具体降级或未导入说明；不能把默认补卡理解成原 BBC 的完整动态选卡。普通卡在实战没有抽到时仍由当前原生策略补齐。

礼装名称无法唯一匹配、各候选缺少工程助战识别模板、仅好友限制等会明确提醒。BBC 冠位筛选可尝试互换普通与报酬礼装槽；原生仍按固定槽位筛选，不会自动交换。导入预览单独显示冠位及羁绊礼装NP50／初始效果；没有指定卡面不代表没有效果筛选。转换不扩充工程资源。

条件分支、波次额外技能、不能等价自然退场的 `replace`、尚无原生菜单的专属指令、其他负号技能、选卡中断点及当前只支持三敌时的第4–6敌选取等无法等价表达，会报错并保留当前方案。例如 `["BBDubai",3,0]`、`["Start",1,[1]]`、`["End"]` 不能当作普通技能导入。

BBC 的动态补卡、暴击优先与链选择不等同于原生高级策略中的某一个预设，导入不会暗中改选全局策略；未固定的卡位及计划结束后的战斗使用当前原生策略。BBC也未提供自有从者逐人礼装和队伍COST上限，转换不会虚构这些值。

转换后的御主礼装用于解释技能与换人；在原生自动编队流程中，工程会按方案指定礼装更换并复核游戏装备。首次使用新转换结果时，建议观察一场实战，确认清波回合和选卡意图。
