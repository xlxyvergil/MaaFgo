# 原生自动战斗羁绊满停止方案

更新日期：2026-11-07。状态：日服五栏布局的指定号位、多选及所有从者模式已通过MaaMCP实测；本次补齐全选模式升级遮挡延后、新升级横幅识别和专用跳过路由，已用留存实拍及真实框架内存控制器回归，尚未完成新分支实机验收。国服及特殊布局仍待实机校准。本文作为该功能的维护依据，后续实现、模板来源和实机验收均在本文更新。

## 用户要求与范围

### 2026-11-02号位多选修订

当前界面改为默认关闭的「羁绊满时停止」总开关，开启后展开原生checkbox「检查号位」，1～6号位默认全选，至少选择一项（兼容现有Schema不使用新版min_count字段，空选时由业务检查提示重新勾选）。MXU及项目安卓端已支持该类型，无需增加六个独立Switch。每个候选通过独立attach布尔字段合并，避免多选时数组相互覆盖；父开关先重置六项，再合并本次选中项，防止取消选择后沿用旧值。

选中任意自有从者MAX即截图停止；助战和空位自动排除。全选保持「所有从者」的整行检测，部分选择按实际编队映射到结算栏；两者遇明确升级遮挡且仍有原定战斗预算时都可延后复核，不额外加场。仅选择助战／空位、无选择或映射未知时给出具体处理提示。运行时保留旧all／slot参数兼容；原界面旧单选值在客户端无法映射新开关时可能恢复默认关闭，升级后需核对开关与号位。

以下早期单选说明与验收记录保留用于追溯；当前选项以本节和实际JSON为准。本轮使用留存图像及离线测试，不连接设备、不开始游戏战斗。

- 新增独立选项「羁绊满时停止」，默认关闭；候选为关闭、所有从者、1～6号位从者。「所有从者」表示任意自有从者满羁绊即停止。
- 仅在已经进入战后结算后检测，必须先于下一步、继续出击和结算兜底点击。**不修改 Python 战斗运行时，不在战斗帧循环增加羁绊检测。**
- 羁绊结算只显示非助战从者。指定位置以出战编队1～6号位为准，必须自行转换成非助战结算栏位，不能把结算第3栏直接当作编队3号位，也不能假定助战固定在3号位。
- 命中后保存检测到的完整截图，保留羁绊结算现场，结束当前根任务中的原生战斗及所有内部连续执行；不点击下一步、不进入下一场。截图写入失败仍停止，并说明失败。
- 判定以羁绊栏显示MAX／最大值为准；普通升级、从者等级MAX、羁绊礼装奖励不单独作为停止依据。启动前已满者在本场结算仍触发。
- 模板先复用本机BBC，记录来源与哈希；通过实战截图逐步替换为项目自有模板。日服正式模板按项目约定放在base/image对应目录。

## 实现结构

### 配置和入口

新增独立options JSON，通过专用配置节点的attach传入模式及槽位，避免高级策略来源切换、Chaldea参数覆盖。挂载到通用战斗方式的native分支、芥学姐连续代打、自动主线、自动清Free和地狱的试炼，在高级策略之前显示；interface.json导入新文件。

### 识别和栏位映射

固定模板、ROI、阈值、等待时间、点击和有界轮询均由Pipeline节点维护。自定义逻辑只负责读取配置、按实际编队生成栏位映射、汇总各栏识别结果、保存证据和设置业务停止状态。MAX匹配限定在羁绊页的对应栏内。

复用InitialFormation.slots中的slot、status、is_support，按原始编队顺序排除助战后建立结算对应关系；少人、空位和无助战布局通过截图校准，不凭BBC五栏坐标猜测六人布局。身份unknown不等于空位，只要占位及助战判断可信，不要求识别姓名。从中途战斗启动或采集缺失导致指定位置映射不可信时，明确停止并提示无法确认目标，不擅自选择其他栏。

结果页初现时先检查输入同帧：页面与目标MAX均明确命中，立即锁存并保存，避免等稳定期间自动升级展示遮住MAX。初帧未命中时，先按100ms间隔、最长2秒快速复核；仍未命中才进入严格冻结检查，要求画面稳定1000ms、总冻结检查限时8秒，并进行有限轮次复核。确认未满后才允许继续；明确识别到羁绊升级展示时，按下述延后规则处理。其他遮挡、截图失败和映射异常仍为未确认停止，不能把未知当未满。时间、次数均由Pipeline配置，实际间隔还包含截图和识别耗时。

### 升级遮挡时下场复核或末场正常结算（2026-11-08用户修订）

- 无遮挡羁绊页能按编队映射确定MAX归属；困难在于刚升级展示可能先于识别遮住羁绊栏，并非平常不能定位从者。
- 若已明确命中目标号位MAX，立即截图停止，不因后续弹窗撤销；所有从者模式明确命中任意MAX也立即停止。
- 全选及指定号位模式在目标尚未确认、画面明确为羁绊升级展示、且外层仍有既定战斗预算时，保存本场证据并标记“升级遮挡，目标待复核”，允许原结算流程继续；下一场在无遮挡结算页按原配置检查。指定号位仍须有可信槽位映射。重新进入编队时采集新证据，未重新编队的连续出击沿用已验证的原编队槽位证据。不能将待复核当作未满，也不能为复核额外增加场次、突破任务上限或改变补充体力设置。
- 2026-11-08按用户修订：明确是单场或最后一场时，已确认的升级展示正常跳过并完成经验、战利品等结算，让当前任务成功返回并继续后续任务；不再因没有下一场可复核而锁存停止，也不额外开战。该许可与“下场复核”独立，不会在末场显示待复核警告。未声明剩余预算仍不能推定为末场，保留原保护；普通识别失败、布局不支持、目标为空位／助战、映射丢失仍停止。
- 升级展示本身不证明已达到当前羁绊上限（例如13之后可能已解锁14），不能照搬BBC“升级后等级≥10即满”的逻辑。正常顺序为羁绊→升级展示（可能）→经验→战利品；只有已登记下场复核或末场正常结算许可的本场升级展示才可由“结算-羁绊升级继续”跳过。后续画面不得覆盖本场许可；新场次、任务开始和结束均清理。明确MAX仍优先停止，不能仅凭末场预算跳过尚未确认的画面。
- 2026-11-07按用户指定的原包资源简化为两种文字模板：左上完整`img_txt_servantbonds01`确认普通羁绊页，右侧完整`img_txt_servantbonds02`确认升级说明，移除原先顶部标题、横幅OCR和卡片LEVEL UP的三条组合路径。两图背景并不透明，使用`tools/generate_bond_text_templates.py`提取金色文字、按1.25倍字号放大并将背景涂为纯绿，Pipeline启用`green_mask`；01是02的前缀，两个节点必须分别限制左上及右侧位置。
- 重新核验发现，达芬奇及龙娘先前保存的大横幅帧处于动画早期，右侧02说明尚未显示，不能将其描述为被立绘遮挡。MaaMCP只截图确认龙娘动画后会自动显示完整说明；当普通页消失而02尚未出现时，有界等待说明，不点击过渡画面。期间再次见到普通页仍优先检查MAX，超时、进入经验／战利品或截图失败则保留现场停止。
- 国日服01、02均来自各服原包文字资源；日服普通页与升级说明已用真实截图回放，国服仅完成原图文字、导出尺寸与资源加载检查，仍待国服实机截图校准。MAX及RESULT素材保持原有来源和阈值。
- 连续战斗（含普通单场和试炼）以剩余battle_count、Free以剩余battle_limit为资格依据；明确还有下一场或明确已到末场分别记录，省略预算为未知。Free后续查找若自然结束，不为了复核额外寻找或发起战斗；只有真正待下场复核的记录才附未复核及证据提示。主线的剩余推进关数可能全为剧情，不能当作剩余战斗次数；当前战斗为最后一个推进阶段时可声明末场，其他阶段保持未知。延后及末场结算许可独立于真正停止，按根任务隔离，下一场及任务结束时清理。
- 本轮完成已存实拍图片、单元和真实框架组件回归，并通过MaaMCP测试日服当前龙娘5→6升级说明页：以全选及重建第5/10场剩余预算为测试设置，匹配0.886312／0.8，正式交接逻辑登记下场复核，正式“结算-羁绊升级继续”节点单击后确认经验页，并在此结束。未续跑打包任务；完整动画过渡及下一场MAX复核由截图回放覆盖。过程、截图、配置及清理回执位于`.workbuddy/runtime/bond-live-pass-20261107/`。

### 结算接入和停止传递

接入通用最终／连续结算及其后续轮询、主线和Free共用的StoryRunner.settle、试炼专用结算。原生runtime.py不新增检测。

AutoBattleAction只在runtime已返回ok且reason为victory后、返回Pipeline之前执行一次战后交接检查；关闭、战败和失败不取额外截图。此检查不进入运行时回合循环，用于避免包装节点默认延迟和截图合计约2秒的交接空档。

开启选项时，将现有「战斗_胜利」的单次TemplateMatch由掉落页「下一步」切换到战后结果标题。仍复用原节点、原调用次数，不新增战斗帧羁绊识别；关闭时恢复原模板和全屏ROI。理由是只等掉落页下一步可能已经错过羁绊结果。日服使用本场完整RESULT自截模板，国服先用BBC战斗结果标题参考，均记录来源。结果标题初现后，仅在战后交接中按50ms间隔、最长5秒有界快速等待羁绊页或羁绊升级展示；MAX输入帧一经确认立即保留，不先阻塞等待升级动画。

不能只使用StopTask：MaaFramework可能将其报告为succeeded，而auto_battle_repeat会按成功继续下一场。因此需独立根任务执行状态保存bond_max停止原因、命中位置、场次和截图路径，repeat及主线／Free外层优先消费此原因，显示「条件达成停止」而非普通失败或全部场次完成。

守卫的next与on_error使用两个独立StopTask出口，分别为「结算-羁绊停止出口」和「结算-羁绊停止异常出口」，二者都终止当前Pipeline。maa-checker禁止两条路由指向同名节点，不能为了共享停止动作而写成同名出口；截图写入失败仍保留停止状态，不得退回继续战斗。

该状态覆盖fight与settle，不依赖编队会话存活。主线／Free目前在fight结束时清理编队会话，所需轻量映射应在清理前保存。状态在新根任务启动、结束和用户停止时清理，防止跨任务串用。

截图保存实际命中的同一帧，遵循Windows／Android各自截图目录；文件名包含时间、场次和命中位置。停止状态先锁存，再尝试写图，防止保存失败恢复出击。

## 稀有满羁绊现场测试保护

最初用户停在日服编队，预计本场结束所长满羁绊。这是难以重现的样本，测试时优先保证现场保留。以下为保护约束；两场实际执行及结果另见下节。

1. 先完成静态、离线和真实框架组件检查，证明MAX检查优先于下一步，停止不会继续下一场。
2. MaaMCP重新发现设备、连接并截图确认当前日服编队；保存原编队和配置证据，不擅自重排或更换角色。
3. 在测试专用override中关闭所有结算盲点、下一步、继续出击及返回动作，失败出口不点击；这些保护只用于本轮测试，不写入正式无限等待。
4. 每轮只执行一次战斗。生产战斗运行时保持不变；仅在临时Agent进程中将Executor.tap_top_right_close包装为空操作，避免极少数提前推进。第一场曾使用测试专用胜利识别覆盖；第二场改用正式选项配置的单次RESULT标题匹配，不再使用测试专用胜利识别。临时防点击保护不写入正式代码，也不作为生产功能验收的替代；运行前核实实际执行链和保护生效。
5. 战斗一结束，首先截图并保存原始结算帧；若未确认进入预期页面，立即停在现场调查，不自动恢复、后退或重启。
6. 在保留的羁绊页上用生产识别和停止逻辑验证，可反复进行只观察复测；采集每栏ROI、匹配分、阈值和编队映射。满羁绊验证完成前不得点击下一步。
7. 每轮MCP均在finally中stop_pipeline并关闭服务，保留日志和现场截图。所有设备操作仅经MaaMCP完成。

若需要其他战斗先验证流程，应先确认不会消耗目标从者的稀有满羁绊机会；不得为了普通流程测试先让同一从者满羁绊。普通Free本也可能沿用游戏内自动使用风暴罐、茶壶等设置，不能按关卡类别或灰色图标推定不会消耗；无法明确核验自动使用状态时，不应承诺保留对应道具。

## 验收标准

- 默认关闭时保持原结算行为，战斗运行时无额外羁绊检测。
- 所有／指定槽位、目标／非目标MAX、未满、普通升级、已满启动均有对应验证。
- 助战不同位置、空位、少人、NPC和无助战布局映射有明确结果；缺失信息不猜测。
- 最终／连续场、主线／Free及试炼均在点击下一步前检测；MAX时不继续出击、不吃苹果、不开始下一关。
- 截图失败仍停止；新任务和不同根任务不继承旧停止原因。
- 修改Pipeline或选项后执行python tools/run_tests.py --suite static，随后运行相关单元和组件测试。
- 实机记录必须说明实际界面、命中节点、分数、截图路径、最终界面与MCP清理结果，不以任务succeeded代替目标分支覆盖。
